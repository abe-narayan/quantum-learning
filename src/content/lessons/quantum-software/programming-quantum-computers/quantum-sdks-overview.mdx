## Motivation

Circuit Representation in Code built one small, platform-specific
circuit abstraction. Real-world quantum programming happens through a
handful of established SDKs. This lesson surveys them at a conceptual
level, not to teach any one's specific syntax, but to show the shared
structure underneath all of them (the same structure this platform's
own `QuantumCircuit` already demonstrates in miniature).

## Engineering Development

### The major SDKs, briefly

- **Qiskit** (IBM): one of the most widely used, tightly integrated with
  IBM's own hardware access; strong ecosystem of add-on libraries for
  specific algorithm families.
- **Cirq** (Google): designed with particular attention to the physical
  constraints of near-term (NISQ, Noise Decoherence & Scaling) hardware,
  giving fine-grained control over circuit scheduling and hardware-specific
  details.
- **PennyLane** (Xanadu): built specifically around hybrid
  quantum-classical differentiable programming, with first-class support
  for the gradient-based optimization VQE and QAOA (Quantum Algorithms
  II) require.

Other SDKs exist (this is not an exhaustive list). The point isn't
memorizing every name, but recognizing the shared underlying pattern.

### The shared structure

Every one of these SDKs follows the same three-part shape this
platform's `QuantumCircuit`/`runCircuit`/`sampleMeasurements` already
built in simplified form: (1) **build** a circuit as a data structure,
(2) target a **backend**, a simulator or a specific piece of real
hardware, to execute it, and (3) **read back results**, typically as
measurement counts over many shots (Qubit Readout Techniques), not a
single exact answer. Framework differences are mostly about ergonomics,
target audience (research vs. production), and which hardware
ecosystem each is most tightly integrated with, not about
fundamentally different computational capability.

### What a backend abstracts over

A "backend" is exactly the abstraction that lets identical circuit code
run against wildly different execution engines: an ideal noiseless
simulator (giving exact amplitudes), a noisy simulator (Simulating
Quantum Systems' noise-simulation lesson), or real hardware
(Physical Qubit Platforms' actual devices, with all of Noise, Decoherence
& Scaling's real error sources). The circuit itself doesn't need to know
or care which backend it's targeting, a genuine, valuable separation of
concerns.

## Physical Interpretation

This lesson is intentionally light on new technical content. Its value
is recognizing that the specific tool (Qiskit vs. Cirq vs. PennyLane)
matters far less than understanding the shared conceptual pattern this
entire course has been building toward, which transfers directly to
whichever specific SDK a reader eventually uses in practice.

## Worked Example

**Why would a research team building VQE-based algorithms specifically
favor PennyLane over a general-purpose SDK?**

VQE (Quantum Algorithms II) requires computing gradients of a
parametrized circuit's output with respect to its parameters, for
classical optimization. PennyLane's differentiable-programming design
is specifically built around making this gradient computation efficient
and ergonomic, whereas a general-purpose SDK might require the
researcher to implement this gradient machinery manually. This is
exactly the kind of ergonomics-driven, not capability-driven,
distinction this lesson emphasizes.

## Common Mistakes

<Callout type="mistake">
**Thinking one SDK can do something fundamentally impossible in
another.** All three (and others) can, in principle, express the same
circuits and run on the same range of backends. Differences are about
convenience and ecosystem fit, not raw computational capability.
</Callout>

<Callout type="mistake">
**Assuming this platform's QuantumCircuit is "a real SDK."** It's a
deliberately minimal illustration of the shared PATTERN real SDKs use,
genuinely useful for understanding the structure, but far short of any
production SDK's actual feature set (error mitigation, hardware-specific
compilation, and much more).
</Callout>

## Summary

- Qiskit, Cirq, and PennyLane are three major real-world SDKs, each with
  a different ecosystem/design emphasis, but sharing the same
  build-target-read structure.
- This platform's `QuantumCircuit` illustrates that same structure in
  simplified form, not a production-grade SDK.
- A "backend" abstracts over WHICH execution engine (simulator or
  hardware) runs a circuit, letting the same circuit code target very
  different systems.
