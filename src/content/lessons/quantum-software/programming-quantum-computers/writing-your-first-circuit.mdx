## Motivation

Every previous lesson in this course discussed the pattern
conceptually. This lesson does it: build a real circuit, run it, and
look at both kinds of output this platform's engine can produce, exact
amplitudes and shot-based samples, end to end.

## Walkthrough

### Step 1: Build the circuit

A **GHZ state** ($\frac1{\sqrt2}(|000\rangle+|111\rangle)$, a 3-qubit
generalization of the Bell state) is built with:

```
const circuit = new QuantumCircuit(3);
circuit.h(0).cnot(0, 1).cnot(1, 2);
```

Nothing has run yet. `circuit.instructions` holds three
`GateInstruction` objects (Circuit Representation in Code), waiting to
be executed.

Build this exact circuit yourself below (H on q0, then CNOT(0,1), then
CNOT(1,2) on 3 qubits) and confirm you get the same two-peak
distribution before reading Step 2's exact numbers.

<LazyCircuitBuilder />

### Step 2: Run it exactly

```
const state = runCircuit(circuit);
```

This platform's engine confirms `state.probabilities()` gives exactly
`[0.5, 0, 0, 0, 0, 0, 0, 0.5]`: probability $0.5$ each for
$|000\rangle$ and $|111\rangle$, zero everywhere else, matching the GHZ
state exactly.

### Step 3: Sample it like real hardware would

```
const counts = sampleMeasurements(state, 5000);
```

Real hardware (and honest simulators) don't hand back exact amplitudes.
They report a finite number of individual measurement shots
(Qubit Readout Techniques). Running this platform's `sampleMeasurements`
with 5000 shots gives counts close to (but not exactly) a 2500/2500
split between "000" and "111", e.g. one representative run gave 2521
and 2479. The deviation from a perfectly even split is genuine
**statistical (shot) noise**, not a bug. It shrinks (relatively) as
shot count grows, following the standard $1/\sqrt{\text{shots}}$
statistical scaling any repeated-sampling estimate obeys.

## Physical Interpretation

The gap between Step 2's exact probabilities and Step 3's sampled counts
*is* the central practical fact of running anything on real quantum
hardware: you never directly observe $|\psi\rangle$'s amplitudes, only
statistics accumulated over many runs, always with finite-shot noise on
top of whatever hardware error (Noise, Decoherence & Scaling) is also
present.

## Worked Example

**Using this platform's confirmed test-suite result (5000 shots on a
Bell state, `00`/`11` split), what range of `00` counts is expected 95%
of the time, treating this as a binomial sampling process?**

For $p=0.5$, $n=5000$: standard deviation
$\sigma=\sqrt{np(1-p)}=\sqrt{5000\times0.25}=\sqrt{1250}\approx35.4$.
A 95% range is roughly $\pm2\sigma\approx\pm71$ around the expected
mean of 2500, so counts between about 2429 and 2571 are expected 95% of
the time, purely from statistical shot noise, with a perfect,
noiseless simulator and an exact 50/50 underlying probability.

## Common Mistakes

<Callout type="mistake">
**Expecting sampled counts to exactly match the underlying probabilities.**
Even with a perfect, noiseless quantum state, finite-shot sampling
always shows statistical fluctuation. The worked example's $\pm71$-count
range at 5000 shots is real and expected, not evidence of a broken
circuit.
</Callout>

<Callout type="mistake">
**Confusing shot noise (statistical, present even for a perfect
simulator) with hardware error (physical, from Noise, Decoherence &
Scaling's actual error sources).** Both contribute to real hardware
results; only shot noise is present in this lesson's idealized
`sampleMeasurements` example.
</Callout>
