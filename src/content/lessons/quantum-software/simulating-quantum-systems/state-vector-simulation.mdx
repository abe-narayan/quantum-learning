## Motivation

This course is called "Simulating Quantum Systems" — but you've already
been simulating quantum systems since this platform's very first lesson.
This opening lesson doesn't introduce new machinery. It stops and names
the technique you've been using all along, pins down its specific
guarantees and specific limits, and sets up the rest of this course's
cost analysis.

## Engineering Development

### What state-vector simulation actually is

A **state-vector simulator** represents an $n$-qubit quantum state
exactly as a list of $2^n$ complex amplitudes, precisely this
platform's `StateVector` class, used without exception in every
Quantum Computing pillar course. Applying a gate updates these
amplitudes directly via ordinary linear algebra (`applySingleQubitGate`,
`applyCNOT`), exact matrix multiplication, not an approximation of any
kind.

### What it guarantees

A state-vector simulator computes the *exact* quantum state (up to
ordinary floating-point rounding, the same kind of error present in any
numerical computation). Every amplitude, every probability, every
expectation value this platform has ever displayed came from this exact
technique. This is fundamentally different from *sampling* (Writing
Your First Circuit's `sampleMeasurements`), which only estimates
probabilities statistically; a state-vector simulation, by contrast,
computes those probabilities exactly.

Watching both side by side on the same circuit makes the distinction
concrete rather than just asserted: the "exact" bars below never move
(they ARE the state-vector answer), while the "sampled" bars are this
page's own live `sampleMeasurements` calls against that exact state,
landing closer to 0.5 as shot count grows, exactly the statistical
convergence Writing Your First Circuit already demonstrated once, here
made explorable across five different shot counts on a fresh Bell
circuit.

### Simulating vs. being

"Simulating a quantum computer" on a classical machine (this platform's
entire engine) and "being a quantum computer" (Physical Qubit Platforms'
actual hardware) compute the *same* mathematical answer for a given
circuit, but by *completely different physical means*. This precision
matters: nothing about this platform's engine is somehow "not really"
quantum mechanics; the linear algebra is exact. But it is being
executed by classical hardware (Simulators vs. Real Hardware's
opposite-failure-modes framing), which is exactly what makes this
course's cost question (next lesson) a real one.

## Physical Interpretation

Every numerical claim this entire platform has ever verified, Grover's
algorithm's success probability, the Bell state's entanglement, the
hydrogen atom's energy levels via a truncated basis, rests on this
exact technique, used without ever being named as such until now. This
lesson's contribution is entirely conceptual: recognizing the common
thread, not adding new capability.

## Worked Example

**Is running `runCircuit` on this platform's `QuantumCircuit` "real
quantum computing," or "just simulation"?**

It's state-vector simulation: exact quantum-mechanical
calculation, computed on ordinary classical hardware. It is NOT running
on an actual quantum device (Physical Qubit Platforms), and so carries
none of real hardware's physical noise (Noise, Decoherence & Scaling).
But it is also not an approximation of the underlying physics in any
way; the amplitudes it computes are exactly what an ideal, noiseless
quantum computer would produce for the same circuit.

## Common Mistakes

<Callout type="mistake">
**Thinking "simulation" means "approximation."** State-vector simulation
computes EXACT amplitudes (up to floating-point precision). The
approximation, when it exists, is in techniques like Tensor Network
Methods (a later lesson in this course), not in the state-vector
approach itself.
</Callout>

<Callout type="mistake">
**Assuming this platform's engine is "not really" doing quantum
mechanics because it runs on classical hardware.** The linear algebra is
exact quantum mechanics; only the substrate executing it (classical bits
and transistors, vs. Physical Qubit Platforms' actual qubits) differs.
</Callout>
