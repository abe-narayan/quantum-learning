## The Same VQE, Written as a Program

Quantum Algorithms II already built <Term id="vqe">VQE</Term> once, computing its ansatz
state by direct matrix arithmetic. This closing lesson implements the
same variational loop the "software" way instead: the circuit-as-data
pattern this track has developed, built from this platform's own
`QuantumCircuit`. Because both code paths compute the same physics,
every result here can be cross-checked against
`exactGroundStateEnergy`, the same verified answers Quantum
Algorithms II already established.

The Hamiltonians in this lesson are deliberately small (one and two
parameters, ground energies known in closed form) because that is what
makes the implementation checkable. The reason anyone builds this
machinery is the case where no closed form exists: a molecular
Hamiltonian whose ground-state energy is the thing you wanted and cannot
get any other way.

## Ansatz, Cost Function, Optimizer

### Building the ansatz with QuantumCircuit

Instead of Quantum Algorithms II's `ansatzState` (a direct matrix
computation), build the identical physical <Term id="ansatz">ansatz</Term> using
`QuantumCircuit`:

```
const circuit = new QuantumCircuit(1);
circuit.ry(0, theta);
const state = runCircuit(circuit);
```

This is the "software" version of the same physics: the
circuit-as-data pattern (Circuit Representation in Code) applied to a
variational algorithm.

### Computing the cost function

For the simplest case, $H=Z$: since $\langle Z\rangle=P(0)-P(1)$
directly from measurement probabilities, no separate matrix-expectation
machinery is even needed.
`state.probabilities()[0] - state.probabilities()[1]` computes
$\langle Z\rangle$ directly from the circuit's own output.

### Extending to a nontrivial Hamiltonian

For $H=0.6Z+0.8X$ (exact ground energy $-1$, since
$\sqrt{0.6^2+0.8^2}=1$), a two-parameter ansatz
(`circuit.ry(0,theta).rz(0,phi)`) with $\langle H\rangle$ computed via
direct matrix application to the circuit's output amplitudes,
grid-searched over both $\theta$ and $\phi$, converges to
$\langle H\rangle\approx-0.9996$, within $0.04\%$ of the true $-1$
ground energy, limited only by grid resolution. A finer grid closes the
gap further, as the Variational Method course established for a
different, continuous-wavefunction trial family.

Unlike the single-parameter case, this cost landscape is
two-dimensional: $\langle H\rangle$ is now a function of a $(\theta,\phi)$
plane, not a single curve. This page's own $15\times15$ grid search,
run live over both parameters, traces out that entire plane as a
color-mapped heatmap, with the grid's own minimum marked directly:

## One Physics, Two Implementations

This is the Quantum Software track's thesis made concrete: one physical
algorithm (VQE, already built in Quantum Algorithms II) admits several
software realizations (direct matrix computation, circuit-as-data), and
when both are correct they agree to the last digit. Software structure
is a real engineering choice, and it changes nothing about the physics
underneath.

## Matching the Exact Ground-State Energy

**Confirm the QuantumCircuit-based single-parameter result matches
Quantum Algorithms II's exactGroundStateEnergy exactly, and explain why
exact (not approximate) agreement is expected here specifically.**

Grid search over `circuit.ry(0,theta)`'s $\langle Z\rangle$ finds the
minimum at $\theta=\pi$ (a grid point landed exactly on it), giving
$-1$, matching `exactGroundStateEnergy(PAULI_Z)=-1` to the full
precision tested. Exact agreement (not just "close") is expected here
because $H=Z$'s ground state is $|1\rangle$ on the nose, and the
$R_y(\theta)$ ansatz family reaches it at $\theta=\pi$, unlike
the two-parameter $0.6Z+0.8X$ case, where the grid search's finite
resolution leaves a small (but shrinkable) residual gap.

## Expecting Two Implementations to Disagree

<Callout type="note">
**Assuming a QuantumCircuit-based and a matrix-based VQE implementation
would give different physics.** They compute the identical underlying
quantities. This lesson's exact agreement with `exactGroundStateEnergy`
confirms this directly, not just plausibly.
</Callout>

<Callout type="note">
**Expecting every optimization to converge exactly, the way the
single-parameter H=Z case did.** The two-parameter case's small residual
gap (grid resolution, not a real physics discrepancy) is the more
typical situation. Exact convergence at $\theta=\pi$ for $H=Z$ is a
special, checkable coincidence of that specific problem's structure.
</Callout>

## Practice Questions

1. Write out (conceptually) the QuantumCircuit-based steps to compute
   $\langle Z\rangle$ for a given $\theta$.

   <details className="answer-reveal">
   <summary>Answer</summary>

   Five steps, of which only one is arithmetic:

   1. Create a one-qubit circuit, `new QuantumCircuit(1)`.
   2. Append the ansatz rotation, `circuit.ry(0, theta)`. This adds one
      `RY` instruction with its angle as a parameter. Nothing has run
      yet, and no state exists.
   3. Execute it, `runCircuit(circuit)`. This allocates $|0\rangle$,
      dispatches the instruction to `applySingleQubitGate`, and returns
      the final `StateVector`.
   4. Read the measurement probabilities off the amplitudes,
      `state.probabilities()`, giving $[P(0),\,P(1)]$.
   5. Subtract: $\langle Z\rangle = P(0)-P(1)$.

   **Why step 5 needs no matrix machinery at all.** $Z$ is diagonal in
   the measurement basis, with eigenvalue $+1$ on $|0\rangle$ and $-1$ on
   $|1\rangle$. Its expectation value is therefore the eigenvalue-weighted
   average of the measurement outcomes, which is exactly
   $(+1)P(0)+(-1)P(1)$. No operator is applied; the expectation is read
   straight out of the probabilities the measurement already produces.

   That is not a trick specific to $Z$, and it is worth generalizing
   correctly. *Any* observable diagonal in the computational basis is a
   weighted sum of measurement probabilities, so any such term is free
   once you have the counts.

   **And it is worth being clear about where it stops.** $X$ is not
   diagonal in that basis, so $\langle X\rangle$ cannot be read off a
   $Z$-basis measurement at all. The two-parameter case in this lesson
   therefore applies the Hamiltonian matrix to the amplitudes directly,
   which a simulator can do and a device cannot. On real hardware the
   equivalent move is to rotate the basis before measuring, one extra
   gate and a *separate measurement setting* per non-commuting term. That
   is precisely why the Hybrid Workflows lesson's cost arithmetic
   multiplies by the number of Pauli terms: each one is its own set of
   circuit executions.

   The wrong turn is thinking step 2 computed something. It appended a
   data object, and the whole build-then-run separation this course
   develops sits in the gap between steps 2 and 3.

   </details>

2. Why does $H=Z$'s ground state land EXACTLY on a grid point
   ($\theta=\pi$) while $H=0.6Z+0.8X$'s optimal parameters don't land
   as precisely on this lesson's grid?

   <details className="answer-reveal">
   <summary>Answer</summary>

   Because one optimum is at a rational fraction of the search interval
   and the other is not. Nothing about the second Hamiltonian is harder;
   the difference is arithmetic about where the target sits.

   **The $H=Z$ case.** With the ansatz $R_y(\theta)|0\rangle$, the cost
   is $\langle Z\rangle=\cos\theta$, minimized at exactly $\theta=\pi$.
   A grid of $n$ points spanning $[0,2\pi]$ with both endpoints included
   has spacing $2\pi/(n-1)$, so $\pi$ is a grid point whenever $n-1$ is
   even, that is, whenever $n$ is odd. The lesson's 41-point grid
   qualifies, and so does a 21-point one: both return exactly $-1$,
   matching `exactGroundStateEnergy(PAULI_Z)`.

   **The $H=0.6Z+0.8X$ case.** Write $H=\hat n\cdot\vec\sigma$ with
   $\hat n=(0.8,\,0,\,0.6)$, a unit vector. The ground state is the $-1$
   eigenvector, whose Bloch vector is $-\hat n=(-0.8,\,0,\,-0.6)$. Its
   polar angle is $\theta^\*=\arccos(-0.6)=\pi-\arctan(4/3)\approx
   2.214297$, with azimuth $\varphi^\*=\pi$. Evaluating the ansatz there
   returns $\langle H\rangle=-1$ exactly.

   Now ask whether $\theta^\*$ can ever be a grid point.
   $\theta^\*/\pi\approx0.70483$, and $\tan\theta^\*=-4/3$. A rational
   multiple of $\pi$ has tangent in $\{0,\pm1\}$ or undefined, so
   $\theta^\*/\pi$ is irrational. **A uniform grid over $[0,2\pi]$ will
   never contain it, at any resolution whatsoever.** The best any grid
   can do is land near it, and the 15-point grid's nearest useful point,
   $\theta=2.24399$, misses by 0.0297 and returns $-0.99955907$: the
   0.04% the lesson quotes.

   The wrong turn is reading the residual as physics, as though the
   variational method were failing or the ansatz were too weak to
   represent the ground state. It is not: the same two-parameter ansatz
   reaches $\langle H\rangle=-1$ to machine precision at
   $(\theta^\*,\varphi^\*)$. The 0.04% belongs entirely to the optimizer,
   and specifically to the decision to search a discrete grid rather than
   a continuous parameter space. Question 4 is about what happens when
   you try to buy your way out of that.

   </details>

3. Explain why building the SAME VQE physics through two different code
   paths (direct matrix vs. circuit-as-data) serves as a
   correctness check on both implementations.

   <details className="answer-reveal">
   <summary>Answer</summary>

   Because a bug in one shows up as a disagreement only if the other does
   not share it, and these two share nothing.

   The circuit path builds an instruction list, dispatches it through
   `applySingleQubitGate` to produce amplitudes, and reads the
   expectation off those amplitudes. `exactGroundStateEnergy` takes the
   Hamiltonian matrix and finds its lowest eigenvalue. No gate-application
   code is common to the two, and no intermediate representation is
   shared. When they agree to the last digit, the agreement is evidence,
   because the space of bugs that would produce the *same* wrong number
   through both routes is very small.

   The question to test any cross-check against is: what would this prove
   if both paths went through the buggy code? That is the criterion, and
   it disposes of three plausible-sounding alternatives.

   **"Both call the same gate helpers, so agreement confirms the
   helpers."** This would make the check vacuous. A shared layer is
   exactly where a common bug hides, and running the same wrong function
   twice produces the same wrong answer twice. The value here comes from
   the paths *not* sharing that layer.

   **"The matrix computation is the reference, so a matching circuit
   result inherits its correctness."** The evidence is symmetric. Neither
   implementation has earned authority over the other, and if they
   disagreed you would not know which to believe without further work.
   What agreement supports is the conjunction, not one side of it.

   **"VQE converges to the ground energy for any correct ansatz, so
   agreement confirms the ansatz was good."** This assumes the
   conclusion. Whether the optimization converged correctly is the thing
   under test.

   **One honest limit**, because "correctness check" can be read too
   strongly. Agreement rules out *independent* bugs. It does not rule out
   a shared conceptual error: if both paths adopted the same wrong sign
   convention for $R_y$, or both misidentified which eigenvalue is the
   ground state, they would agree and both be wrong. Two independent
   implementations agreeing is strong evidence and not a proof, which is
   why this platform pairs it with checks against closed-form answers
   wherever a closed form exists.

   </details>

4. What would you expect to happen to the two-parameter case's residual
   gap (currently $\approx0.04\%$) if the grid resolution were doubled?

   <details className="answer-reveal">
   <summary>Answer</summary>

   **The expected answer is that it falls by about a factor of four. What
   actually happens on this grid is that it does not move at all.** Both
   halves are worth having.

   **The reasoning behind the factor of four.** Near a smooth minimum the
   cost is quadratic: $f(\theta^\*+\delta)-f(\theta^\*)\approx
   \tfrac12 f''\delta^2$. A grid of spacing $h$ guarantees some point
   within $h/2$ of the optimum, so the worst-case gap scales as $h^2$.
   Halve $h$ and the gap should quarter. As an asymptotic law, averaged
   over where the optimum happens to fall, that is correct.

   **What the engine actually returns.** Refining the lesson's
   $15\times15$ grid the natural way, keeping both endpoints so the point
   count goes $15\to29\to57$:

   $15\times15$, 225 evaluations, gap $4.4093\times10^{-4}$, 0.04409%;

   $29\times29$, 841 evaluations, gap $4.4093\times10^{-4}$, 0.04409%;

   $57\times57$, 3,249 evaluations, gap $4.4093\times10^{-4}$, 0.04409%.

   Identical to eight decimal places, for fourteen times the work.

   **Why.** Doubling a grid this way is *nested*: every old point is
   still a point of the new grid, so the previous winner remains a
   candidate and refinement helps only if a newly added point beats it.
   The $15$-grid's winner at $\theta=2.24399$ sits only 0.0297 from
   $\theta^\*\approx2.214297$, which is unusually close for a grid that
   coarse, and the new points at each refinement all land further away.
   Only at $113\times113$ does a new point at $\theta=2.18789$ finally
   edge it out, improving the gap to 0.03485%, and it takes
   $225\times225$ and 50,625 evaluations to reach 0.00014%.

   **And doubling the other way makes it worse.** Go $15\to30$ instead,
   so the endpoints shift and the grids are not nested, and the gap rises
   to 0.11366%: refining the search by 4× the evaluations returned an
   answer nearly three times further from the truth. The gap is a step
   function of resolution, not a smooth curve, because it depends on
   where the nearest available point happens to fall.

   Two things to take from this.

   **Grid search scales terribly.** In $d$ parameters, doubling the
   resolution multiplies the evaluations by $2^d$. Here $d=2$, so 4×. A
   realistic VQE with a dozen parameters would pay $2^{12}=4096\times$
   the circuit executions per refinement, on top of the shots-per-term
   arithmetic from Hybrid Workflows. This is why grid search is a
   teaching optimizer and gradient methods are what anyone actually runs.

   **The gap is not a floor.** It belongs to the optimizer, not to the
   ansatz. $R_y(\theta)R_z(\varphi)$ reaches $\langle H\rangle=-1$ to
   machine precision at $(\theta^\*,\pi)$, so a continuous optimizer
   closes the gap entirely rather than shrinking it. Buying resolution
   is the expensive way to approach an answer a better search finds
   directly.

   </details>
