## Correcting errors was never free

Every code in this course has been described as though correcting errors
were free. It is not. Each code spends physical qubits, and each of those
qubits is itself capable of failing, which raises a question the course has
so far dodged: can adding error correction ever make things worse?

It can, and the **<Term id="quantum-threshold-theorem">threshold theorem</Term>** says precisely when. Answering it
also closes the loop back to Quantum Algorithms II's capstone, which named
fault-tolerant hardware as the missing ingredient for factoring at
cryptographic scale without saying what that would cost.

## The threshold's logic, and honest overhead

### The qualitative logic of the threshold

A distance-$d$ code fails (produces an uncorrected logical error) roughly
when *more than* $d/2$ physical qubits have errors, a specific, rare
combination out of many possible ways errors could land. If the physical
per-qubit error rate $p$ is small, the probability of $d/2$ or more errors
occurring together shrinks *faster* than $d$ grows (a combinatorial fact:
the number of ways to choose $d/2$ specific failing qubits out of $n$
grows polynomially in $d$, but the probability of any specific
combination all failing shrinks exponentially in $d/2$), so increasing
$d$ (a bigger surface code grid, say) drives the logical error rate
toward zero. This only works while $p$ is below some critical value, the
**threshold** $p_{\text{th}}$: above it, more physical qubits mean *more*
opportunities for errors to combine, and increasing $d$ makes the <Term id="logical-error-rate">logical
error rate</Term> *worse*, not better.

**Concatenation** reaches the same tradeoff by a different route: instead
of building one bigger code (a larger surface-code grid), encode each
physical qubit of a distance-$d$ code in another copy of that same code,
one level deeper. Effective distance compounds with each added level,
while physical qubit count multiplies by roughly $n$ per level, so the
identical below/above-$p_{\text{th}}$ logic applies to adding
concatenation levels exactly as it does to growing a single code's
distance: a net win only below threshold, a net loss above it.

The shape of this crossover, not the real surface-code threshold value,
is what a simple toy model can show honestly: treat $d$ physical qubits
as failing independently with probability $p$ each, majority-vote style,
and the code fails once more than $d/2$ of them fail. This is a genuine
binomial-tail computation, real classical probability math, deliberately
using a toy threshold ($p=0.5$ for independent majority voting) far
above the real, literature-cited surface-code figure below, purely to
make the qualitative crossover visible without claiming a realistic
number. Before sweeping it, make a call:

### Why this platform doesn't derive p_th's actual value

The threshold's numeric value depends on the specific code, the physical
noise model, and the decoding algorithm used. It's an empirical,
code-specific calculation, often done by large-scale numerical
simulation in the research literature, not something derivable from the
qualitative combinatorial argument above alone. Commonly cited figures
for surface codes are in the rough neighborhood of $p_{\text{th}}\sim
0.5$–$1\%$ per gate, cited here as a widely-referenced approximate
figure from the literature, explicitly **not** a number the course's
own (much smaller, 3-qubit) codes derive or verify.

### Resource overhead, honestly scoped

Reaching a low enough logical error rate for a long computation (like
factoring a cryptographically relevant number via Shor's algorithm, from
Quantum Algorithms II) is estimated, in published research, to need on
the order of **hundreds to low thousands of physical qubits per logical
qubit**, depending heavily on the target error rate, the exact code, and
the specific algorithm's circuit depth. This is, again, a cited
range from the literature; the course's own 3-qubit codes and the
$[[9,1,3]]$ Shor code are far too small to derive such a figure, and no
claim is made that they could.

## Closing the gap the algorithms capstone left

This closes the gap Quantum Algorithms II's capstone left open. Shor's
algorithm needs one long circuit to succeed in a single shot at
cryptographically relevant scale, which requires physical error rates
safely below threshold and a code with <Term id="code-distance">distance</Term> large enough to suppress
the residual logical error rate across the whole circuit's duration.

VQE and QAOA tolerate a far higher effective error rate because their
hybrid structure needs no single circuit execution to be perfect. That is
the same distinction the earlier capstone drew, now with the reason
attached: fault tolerance is expensive, and only one of the two families
has to pay for it.

## A distance-3 code above threshold

**Using the qualitative threshold argument, explain (without citing a
specific number) why a distance-3 code run on hardware with physical
error rate well above $p_{\text{th}}$ would perform *worse* than using no
error correction at all.**

Error correction adds physical qubits and additional two-qubit gates
(the syndrome-extraction CNOTs from Lesson 2); each new gate is itself
an opportunity for a new physical error. Above threshold, the rate at
which these *extra* gates introduce new errors outpaces the rate at which
the code corrects existing ones, so the *net* logical error rate is
higher with the code running than without it. Lesson 6's weight-2 worked
example is the same failure in miniature: run past the code's design
limit, the recovery step converted a two-qubit physical error into a full
logical one. Above threshold, that outcome stops being the exception and
becomes the usual case.

## More error correction is not always better

machinery can introduce more error than it removes.

## Practice Questions

1. Using the combinatorial argument, explain qualitatively why a
   distance-5 code's failure probability (needing $\geq3$ simultaneous
   errors) is lower than a distance-3 code's (needing $\geq2$) at the
   same small physical error rate $p$.

   <details className="answer-reveal">
   <summary>Answer</summary>

   Because failure needs one more coincidence, and each additional
   required coincidence multiplies the probability by another factor of
   $p$. A polynomial number of extra chances cannot keep up with that.

   Keep only the dominant term in each tail, the minimum number of
   failures that does the damage:

   $$
   P_3 \approx \binom{3}{2}p^2 = 3p^2,
   \qquad
   P_5 \approx \binom{5}{3}p^3 = 10p^3,
   \qquad
   \frac{P_5}{P_3} \approx \frac{10}{3}p.
   $$

   The bigger code has more ways to fail, $10$ against $3$, which is the
   polynomial part; but it needs a rarer event to do it, $p^3$ against
   $p^2$, which is the exponential part. For small $p$ the exponential
   part wins by a mile. At $p=10^{-3}$ that ratio is about $1/300$, so
   the distance-5 code fails roughly three hundred times less often. At
   $p=10^{-4}$ it is three thousand times less often. Every step up in
   distance adds a power of $p$, which is why the logical error rate can
   be driven arbitrarily low by a code family with a size dial.

   The leading-order estimate also shows you where the argument stops.
   The ratio $\tfrac{10}{3}p$ reaches $1$ at $p=0.3$, which looks like it
   should be the crossover. The exact binomial tails are worth carrying
   out, because they say something cleaner. Writing them in full,

   $$
   P_3 = 3p^2-2p^3,
   \qquad
   P_5 = 10p^3-15p^4+6p^5,
   $$

   and setting them equal gives $(p-1)^2(2p-1)=0$. The only crossing
   below $1$ is at $p=\tfrac12$ exactly, which is this toy model's
   threshold, the same $0.5$ the slider above flattens at. Below it,
   distance 5 beats distance 3 and every further step keeps winning.
   Above it, the ordering reverses and every step makes matters worse.
   The leading-order estimate was conservative, and it was the neglected
   $(1-p)$ factors, the requirement that the *other* qubits survive, that
   made up the difference.

   </details>

2. Why does the threshold depend on the *decoding algorithm* used, not
   just the code's stabilizer structure? (Hint: recall Lesson 6's
   distinction between "detected" and "correctly recovered.")

   <details className="answer-reveal">
   <summary>Answer</summary>

   Because the code produces a syndrome and the decoder produces a
   correction, and the threshold is defined by whether the *correction*
   is right. Those are two different pieces of the system, and only the
   first is fixed by the stabilizers.

   Lesson 6 drew the line precisely: a syndrome does not name an error,
   it names a whole coset of errors that share it. The stabilizer
   structure determines which errors are distinguishable in principle.
   Choosing which member of the coset to blame is the decoder's job, and
   it is a guess, informed by a model of what noise is likely. Swap the
   decoder and you swap the failure rate, on identical hardware running
   an identical code, so the physical error rate at which encoding stops
   paying for itself moves too.

   The gap is not marginal. For the surface code, a decoder that ignores
   the correlation between the $X$ and $Z$ halves of a $Y$ error is
   throwing away real information about where the error chain went, and
   pays for it in threshold. Minimum-weight perfect matching does much
   better than any lookup-style rule, and full maximum-likelihood
   decoding does better still. Published thresholds for one and the same
   surface code span roughly an order of magnitude across the range from
   simple decoders under idealized noise to practical decoders under
   circuit-level noise with faulty measurements, which is the range this
   lesson's cited $0.5$ to $1\%$ figure sits at the pessimistic end of.
   Quoting a threshold without naming the decoder and the noise model is
   not quite meaningful.

   There is a second, more brutal way the decoder enters, and it belongs
   in the same answer. Speed counts. A decoder that is accurate but
   slower than the syndrome measurement rate accumulates a backlog that
   grows without bound, and by the time a correction is computed the
   state it applied to has moved on. In practice that behaves exactly
   like a worse threshold, since the useful figure is the logical error
   rate of the running machine, not of an offline analysis of its logs.

   The wrong turn is to file this as an engineering detail underneath a
   physics result. The threshold theorem is a statement about a
   *scheme*: a code, a noise model, and a decoder, together. Change any
   one and the number changes.

   </details>

3. Referring back to Quantum Algorithms II's capstone, explain in your
   own words why VQE's hybrid structure makes it comparatively insensitive
   to being run somewhat above a hypothetical "threshold" for its own
   error tolerance, in a way Shor's algorithm's circuit is not.

   <details className="answer-reveal">
   <summary>Answer</summary>

   Because VQE's quantum step outputs an average and Shor's outputs a
   single interference pattern. Averages degrade smoothly under noise.
   Interference patterns do not; they wash out.

   Look at what each algorithm asks the hardware for. VQE runs a shallow
   circuit many times, measures Pauli expectation values, and hands one
   number, the energy, to a classical optimizer. Noise perturbs that
   number. The optimizer does not need it to be correct, only to be
   monotone enough locally that stepping downhill still goes downhill,
   and the variational principle keeps a one-sided grip on the result:
   whatever state the noisy circuit prepares, mixed or not, that state's
   energy is still an upper bound on the true ground energy. The bound
   is on the prepared state rather than on the estimate of it, so
   readout error and finite sampling can still put a measured number
   below it, but the error the circuit itself makes has a sign. Errors
   move an estimate, and moving an estimate leaves an estimate.

   Shor's circuit is one long coherent computation whose entire output is
   the phase held in the counting register. That phase exists only as a
   pattern of relative amplitudes across an exponentially large
   superposition, and the inverse QFT's job is to concentrate it onto one
   string. Every gate that fails perturbs the pattern, so the probability
   that the run survives intact falls roughly as $(1-p)^{G}$ with $G$ the
   gate count, and at cryptographic scale $G$ is astronomical. There is
   no averaging structure to fall back on: a corrupted run does not give
   you a slightly wrong period, it gives you a uniform-looking sample
   with no period in it, and averaging noise gives noise.

   That is the asymmetry, and it is worth stating as a general rule
   rather than a fact about two algorithms. Sampling-based algorithms
   that estimate an expectation value tolerate noise as a bias to be
   fought with more shots. Algorithms whose answer lives in a
   phase relationship maintained across a long circuit tolerate noise
   only until the coherence budget runs out, after which they fail
   completely rather than gradually.

   Two honest qualifications, because the question's framing is looser
   than it looks. First, VQE has no code and therefore no threshold; the
   scare quotes in the question are doing real work, and "somewhat above
   its own threshold" means only "noisier than you would like", not
   anything with a theorem behind it. Second, VQE's robustness is
   routinely overstated, and the algorithms capstone said so. Noise does
   not merely offset the landscape, it flattens it, and at scale
   noise-induced barren plateaus can leave the optimizer with no gradient
   to descend at all. VQE is graceful under the noise levels of small
   problems. Nobody has shown it stays graceful at the sizes where it
   would beat a classical computer, and that gap is the honest limit of
   this comparison.

   </details>

4. If a real device's physical error rate is confirmed below
   $p_{\text{th}}$, does that guarantee today's hardware can already run
   a cryptographically relevant factoring computation? What else does the
   resource-overhead discussion suggest is still needed?

   <details className="answer-reveal">
   <summary>Answer</summary>

   No. Below threshold is a necessary condition, not a sufficient one.
   It says the logical error rate *can* be driven down by adding
   distance. It says nothing about how much distance, how many qubits
   that costs, or whether you have them.

   Being below threshold is a statement about the sign of a slope. What
   determines the bill is how far below you are, because the suppression
   you get per unit of distance depends on the ratio $p/p_{\text{th}}$. A
   device sitting just barely under the line needs an enormous code to
   reach a useful logical error rate; one an order of magnitude under
   needs a far smaller one. "Below threshold" and "below threshold with
   margin" are different machines.

   Four other things the overhead discussion points at.

   Scale. The cited figure is hundreds to low thousands of physical
   qubits per logical qubit, and a cryptographically relevant factoring
   run needs thousands of logical qubits. Multiplying those gives
   millions of physical qubits. Today's largest devices are three or four
   orders of magnitude short, and no threshold result closes that gap.

   Non-Clifford gates. Threshold statements typically cover Clifford
   operations and measurement, which are the cheap part. Shor's circuit
   needs $T$ gates, and in a surface code those arrive through magic
   state distillation, a separate factory occupying its own large block
   of qubits and its own share of the runtime. In published resource
   estimates that factory is often the dominant cost, and it is not
   included in a per-qubit error rate.

   Time. The wall clock matters as much as the qubit count. Each logical
   operation costs many rounds of syndrome extraction, and estimates for
   cryptographic factoring run to hours or days of continuous operation.
   The machine has to stay calibrated and stable for that entire
   duration, with a real-time decoder keeping pace throughout.

   The noise model behind the number. A threshold is quoted against a
   specific model, and a device "below threshold" under independent
   depolarizing noise may not be under what it actually experiences:
   leakage out of the computational subspace, crosstalk, correlated and
   drifting errors, none of which the idealized figure covers.

   The Willow result the lesson cites is worth placing precisely against
   all this, because it is easy to over-read. It showed one logical
   qubit's error rate falling as the patch grew from distance 3 to 5 to
   7. That is the sign of the slope, measured, on real hardware, and it
   is a genuine milestone. It is not a computation, and it is not a
   machine.

   </details>

## Summary

- The threshold theorem: below a critical physical error rate
  $p_{\text{th}}$, increasing code distance drives logical error rate
  toward zero; above it, more error correction makes things worse.
- $p_{\text{th}}$'s actual value and realistic qubit-overhead figures are
  cited from the literature, explicitly not derived by this platform's
  own small, distance-3 codes.
- This closes the loop to Quantum Algorithms II: Shor's algorithm's need
  for fault-tolerant hardware is exactly the "below threshold, high
  enough distance" regime this lesson describes; VQE/QAOA's NISQ-friendliness
  is exactly why they don't need it.
