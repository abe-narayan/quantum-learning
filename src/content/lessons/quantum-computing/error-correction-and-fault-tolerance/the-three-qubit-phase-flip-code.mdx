## The obvious next move, and why to skip it

The last lesson's code is blind to phase errors, so the obvious next move
is to design a second code that catches them. Don't. Designing codes is
hard, and this one is already written.

A single identity, $HXH=Z$, turns the entire bit-flip code (encoding,
syndrome extraction, decode table, all of it) into a phase-flip code by
surrounding every step with Hadamards. Nothing about the circuit's
structure changes. Only the basis it operates in does.

## One identity, and the code that falls out of it

### The key identity: Z = HXH

$$
HXH = \begin{pmatrix}\frac1{\sqrt2}&\frac1{\sqrt2}\\\frac1{\sqrt2}&-\frac1{\sqrt2}\end{pmatrix}\begin{pmatrix}0&1\\1&0\end{pmatrix}\begin{pmatrix}\frac1{\sqrt2}&\frac1{\sqrt2}\\\frac1{\sqrt2}&-\frac1{\sqrt2}\end{pmatrix}
$$

Multiplying $XH$ first: $XH=\begin{pmatrix}\frac1{\sqrt2}&-\frac1{\sqrt2}\\\frac1{\sqrt2}&\frac1{\sqrt2}\end{pmatrix}$
(swapping $H$'s two rows). Then $H(XH)$:
row 0 of $H$, $\left(\frac1{\sqrt2},\frac1{\sqrt2}\right)$, dotted with
$XH$'s columns $\left(\frac1{\sqrt2},\frac1{\sqrt2}\right)$ and
$\left(-\frac1{\sqrt2},\frac1{\sqrt2}\right)$ gives $(1,0)$; row 1,
$\left(\frac1{\sqrt2},-\frac1{\sqrt2}\right)$, gives $(0,-1)$. Result:
$\begin{pmatrix}1&0\\0&-1\end{pmatrix}=Z$, confirming $HXH=Z$ exactly
(and by the same computation with $H^2=I$, $HZH=X$: the relationship
runs both directions).

### Turning the code around

If $U$ is any circuit built from $X$ gates and <Term id="cnot-controlled-gates">CNOTs</Term> (like the bit-flip
code's encoder and error), then $H^{\otimes n}UH^{\otimes n}$ replaces
every $X$ in $U$ with $HXH=Z$, because inserting $HH=I$ between every
pair of gates in $U$ conjugates each one individually. (The CNOTs get
conjugated too, and they do not come back unchanged:
$H^{\otimes 2}\,\text{CNOT}(0,1)\,H^{\otimes 2}=\text{CNOT}(1,0)$,
control and target exchanged. That is why the implementation below sandwiches the pipeline
between two Hadamard layers instead of rewriting its gates one by one:
the CNOTs it runs in between are then literally the bit-flip code's own.)
Applying $H$ to every qubit before and after the *entire* bit-flip
pipeline therefore converts an $X$-error-correcting code into a
$Z$-error-correcting code, with the identical CNOT structure running
underneath and an identical decode table read off it.
`encodePhaseFlipCode` and `runPhaseFlipCorrectionCycle` implement exactly
this: encode via `encodeBitFlipCode`, then $H$ on every qubit; correct by
un-Hadamarding, running the ordinary bit-flip correction cycle, then
re-Hadamarding.

### Checked against the engine, not left as algebra

For an arbitrary $\alpha,\beta$, a $Z$ error on any one of the three
qubits is detected and corrected exactly by this construction, checked
directly (to floating-point precision, accounting only for ordinary
numerical error) for all three qubit positions, plus the no-error case.

One thing the derivation above has not spelled out is what the codewords
themselves become, and working that out is the fastest way to see why a
bit-flip detector catches phase errors at all.

## The same code, seen in a rotated basis

The phase-flip code is not a second piece of engineering. It is the *same*
code, viewed in a rotated <Term id="basis">basis</Term>.

This pattern recurs throughout quantum information, and it is worth
learning to look for. Two constructions that appear unrelated often turn
out to be one construction seen from two angles, and finding the
conjugation that connects them saves the work of building the second.

## The companion identity, in two lines

**Confirm $HZH=X$ using $H^2=I$ and $HXH=Z$ directly, without a separate
matrix computation.**

From $HXH=Z$, left-multiply both sides by $H$ and right-multiply by $H$:
$H(HXH)H=HZH$, i.e. $(HH)X(HH)=HZH$. Since $HH=I$: $IXI=HZH$, so
$X=HZH$, exactly the claimed reverse relationship, derived from the
forward one algebraically rather than recomputed from scratch.

## This needs no separate derivation

<Callout type="note">
**Assuming the phase-flip code needs a separate derivation.** It does not.
Encoding, syndrome CNOTs and decode table are all identical to the
bit-flip code's, conjugated by $H$. Deriving it from scratch duplicates
work the $HXH=Z$ identity does in one line.
</Callout>

<Callout type="warning">
**Forgetting to un-Hadamard before running the ordinary bit-flip
correction cycle.** `runPhaseFlipCorrectionCycle` explicitly applies $H$
to every qubit *before* calling the bit-flip correction logic and again
*after*. Omitting either step would run bit-flip syndrome extraction on
a state still in the wrong basis.
</Callout>

## Practice Questions

1. Verify $HYH=-Y$ directly (using $Y=iXZ$ from Lesson 1,
   plus $HXH=Z$ and $HZH=X$).

   <details className="answer-reveal">
   <summary>Answer</summary>

   Substitute, insert $HH=I$ in the middle, and use the two identities
   already in hand:

   $$
   HYH = H(iXZ)H = i\,HX\,(HH)\,ZH = i\,(HXH)(HZH) = i\,ZX.
   $$

   Now $ZX$ is not $XZ$. Multiplying them out,

   $$
   ZX=\begin{pmatrix}1&0\\0&-1\end{pmatrix}\begin{pmatrix}0&1\\1&0\end{pmatrix}=\begin{pmatrix}0&1\\-1&0\end{pmatrix}
   = -\begin{pmatrix}0&-1\\1&0\end{pmatrix} = -XZ,
   $$

   so $HYH = i(-XZ) = -(iXZ) = -Y$.

   The step doing the work is the anticommutation $ZX=-XZ$. $H$ turns $X$
   into $Z$ and $Z$ into $X$, which reverses the order of the product
   $XZ$, and reversing the order of two anticommuting operators costs a
   minus sign. Nothing else in the calculation can produce one.

   Two readings of the result, both useful later. Geometrically, $H$ acts
   on the Bloch sphere as a half-turn about the diagonal axis in the
   $x$-$z$ plane: it exchanges the $x$ and $z$ axes, and a proper
   rotation that swaps two axes has to reverse the third, which is the
   $y\to-y$ that $HYH=-Y$ records. Operationally, that minus sign is a
   global phase. If a $Y$ error strikes one qubit of a register, $-Y_j$
   and $Y_j$ leave the register in the same physical state. So under
   Hadamard conjugation a $Y$ error is a $Y$ error: it is the one
   single-qubit error type this basis change cannot move anywhere else,
   which is why questions 3 and 4 end where they do.

   </details>

2. Explain why a $Z$ error on the bit-flip code (without the Hadamard
   conjugation) produces syndrome $(0,0)$, "no error detected," even
   though an error occurred, using the fact that $Z$ only changes <Term id="global-relative-phase">relative
   phase</Term>, not which computational-basis term has amplitude.

   <details className="answer-reveal">
   <summary>Answer</summary>

   Because the syndrome ancillas are fed by CNOTs, and a CNOT reads a bit
   value. $Z$ is diagonal in the computational basis, so it changes no
   bit value in any term. There is nothing for the checks to catch.

   Written out, with the error on qubit 1:

   $$
   \alpha|000\rangle+\beta|111\rangle
   \;\xrightarrow{\;Z_1\;}\;
   \alpha|000\rangle-\beta|111\rangle.
   $$

   Both terms still have three agreeing bits, so $q_0\oplus q_1=0$ and
   $q_1\oplus q_2=0$ in each, and the ancillas read $(0,0)$ with
   certainty. The damage is entirely in the relative sign between the two
   branches, and no parity of bit values is a function of that sign.

   Worth noticing: $Z_0$, $Z_1$ and $Z_2$ all produce the *same* state
   here, since each one contributes $+1$ to $|000\rangle$ and $-1$ to
   $|111\rangle$. So the error is not merely undetected, it is
   unlocatable in principle. Even a syndrome that somehow announced "a
   $Z$ happened" could not say where, because the three possibilities are
   physically identical on the code space.

   The tempting wrong turn is to treat this as a shortage of checks and
   reach for more ancillas or more qubits. It is not a shortage; it is a
   structural fact about which operators commute. Every check the
   bit-flip code can build is a product of $Z$s, and $Z$ operators
   commute with each other, so no such check will ever anticommute with a
   $Z$ error and flip its eigenvalue. Adding a hundred $Z$-type parity
   checks buys nothing. What this lesson does instead is leave the checks
   completely alone and rotate the frame they are read in, so the errors
   you care about arrive as bit flips.

   </details>

3. If both an $X$ error and a $Z$ error hit the *same* physical qubit
   (together forming, up to phase, a $Y$ error), can either the bit-flip
   code alone or the phase-flip code alone correct it? What would be
   needed to correct this combined case?

   <details className="answer-reveal">
   <summary>Answer</summary>

   Neither can. Each one repairs its own half and hands you a clean
   logical error of the other kind, which is arguably worse than failing
   visibly.

   Run $Y_1$ (that is $X_1$ and $Z_1$, up to the phase $i$) through the
   bit-flip code. The $X_1$ part is seen and located: the syndrome comes
   out $(1,1)$, the table points at qubit 1, and $X_1$ is applied. What
   is left over is $Z_1$ on the encoded state, giving
   $\alpha|000\rangle-\beta|111\rangle$: the logical $Z$. The cycle
   reports a successful correction and the logical qubit has a phase
   error.

   The phase-flip code fails in the mirror image. Its codewords are
   $|+++\rangle$ and $|---\rangle$, and since $X|+\rangle=|+\rangle$
   while $X|-\rangle=-|-\rangle$, an $X$ on any single qubit multiplies the
   second codeword by $-1$ and leaves the first alone. That is the logical
   $Z$ of the phase-flip code, and it commutes with both of that code's
   stabilizers $X_0X_1$ and $X_1X_2$, so it is invisible. The $Z_1$ part
   gets corrected; the $X_1$ part passes straight through.

   What is needed is two layers of protection rather than one, arranged
   so that a single physical qubit is watched by both. That is
   concatenation, and it is the next lesson: encode a logical qubit
   against phase flips into three qubits, then encode each of those three
   against bit flips into three more, giving nine. A $Y$ on any physical
   qubit is caught as an $X$ by whichever inner block contains it and as
   a $Z$ by the outer layer, and because $Y=iXZ$, undoing the two halves
   separately undoes the whole thing.

   The obvious cheaper idea is worth killing explicitly, because it looks
   like it should work: keep three qubits and just measure both codes'
   checks, $Z_0Z_1$ and $Z_1Z_2$ alongside $X_0X_1$ and $X_1X_2$. You
   cannot. Two Pauli strings commute when they anticommute on an even
   number of qubits, counting only the sites where both act
   nontrivially with *different* Paulis. $Z_0Z_1$ and $X_1X_2$ have one
   such site, qubit 1, and no other, so the count is odd: they
   anticommute, and cannot both be measured without one randomizing the
   other. There is also no room for them: three qubits
   holding one logical qubit leave exactly $3-1=2$ independent
   stabilizers, and you have already used both. More qubits is not a
   concession here, it is the requirement.

   </details>

4. Using $H^{\otimes n}UH^{\otimes n}$'s general gate-replacement property,
   predict what conjugating a $Z$-detecting syndrome circuit by $H$ again
   would produce.

   <details className="answer-reveal">
   <summary>Answer</summary>

   The original bit-flip code, unchanged. Conjugation by $H$ is its own
   inverse, so the second sandwich undoes the first:

   $$
   H^{\otimes n}\big(H^{\otimes n}UH^{\otimes n}\big)H^{\otimes n}
   = \big(H^{\otimes n}H^{\otimes n}\big)\,U\,\big(H^{\otimes n}H^{\otimes n}\big) = U,
   $$

   since $H^2=I$ on every qubit. Gate by gate, the same thing is visible:
   the $Z$s go back to $X$ by $HZH=X$, the CNOTs that had exchanged
   control and target exchange them back, and the codewords
   $|+++\rangle,|---\rangle$ return to $|000\rangle,|111\rangle$.

   So this construction has exactly two members and no third. It is
   tempting to expect a chain, bit flip to phase flip to something else,
   and to hope the something else is a $Y$-detecting code that would
   solve question 3 for free. There is no such step, and question 1 says
   why in one line: $HYH=-Y$. The $y$ axis is the fixed axis of this
   conjugation. $H$ moves $X$ and $Z$ into each other's places and leaves
   $Y$ where it is, so no amount of Hadamard sandwiching produces a code
   that treats $Y$ as its primary error.

   A different conjugator would move it. $SXS^\dagger=Y$, so surrounding
   the bit-flip code with phase gates does yield a code that catches $Y$
   errors, at the price of turning its CNOTs into controlled-$Y$ gates.
   That is a curiosity rather than a fix, because "only $Y$ errors" is
   not an error model any real device presents. The useful move is the
   one the next lesson makes: stop conjugating and start nesting.

   </details>

## Summary

- $HXH=Z$ (and $HZH=X$) is an exact algebraic identity, derived by direct
  matrix multiplication.
- Conjugating the entire bit-flip code by $H^{\otimes n}$ converts it into
  a phase-flip code with identical structure underneath.
- Verified directly: a $Z$ error on any of the three qubits is detected
  and corrected exactly, for arbitrary $\alpha,\beta$.
- Practice Question 3 previews this course's next real gap: neither code
  alone corrects a combined $X$-and-$Z$ error on the same qubit, the
  Shor code's actual purpose.
