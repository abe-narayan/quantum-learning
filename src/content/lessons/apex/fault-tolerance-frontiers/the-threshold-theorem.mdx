## The Objection That Nearly Ended the Field

By the mid-1990s, Peter Shor's factoring algorithm had already shown that
a quantum computer could, in principle, outrun every known classical
algorithm at a problem the world's cryptography depended on. But a
serious, well-founded objection immediately followed: quantum states
decohere continuously. Classical error correction assumes errors are
discrete and rare; a qubit's amplitude can drift by an arbitrarily small,
continuous amount, and naively, it looked like *any* nonzero noise rate
would eventually corrupt a long computation beyond repair, no matter how
good your error-correcting code. Some serious physicists doubted
quantum computation could ever be made robust against realistic,
continuous noise at all, not as an engineering difficulty but as a
matter of principle.

The **quantum threshold theorem** answered the objection directly.

<HistoricalMoment date="1996–1998">
  Several groups prove the quantum threshold theorem independently, with
  different constructions and proof techniques: Shor's own
  fault-tolerant constructions, Aharonov and Ben-Or, Kitaev, and Knill,
  Laflamme, and Zurek among them.
</HistoricalMoment>

It showed that continuous noise is not the problem
it first appears to be: discretizing errors via syndrome measurement
(the subject of this course's earlier lessons) combined with
**concatenation** (nesting a code inside itself, recursively) can
suppress logical error *arbitrarily far*, provided the physical error
rate per gate sits below a fixed constant $p_{\text{th}}$, the
**threshold**. This is arguably the single most historically important
theorem in the field: it converted "quantum computing is an interesting
theoretical curiosity that any real noise will eventually destroy" into
"quantum computing is a scalable engineering target: build hardware
below threshold, and error correction provably does the rest."

## The Recursion, Unrolled

### One level: why a logical error needs two physical faults

Take a distance-3 code that corrects any single error: the Steane
$[[7,1,3]]$ code, familiar from the CSS-code
coverage in Quantum Mastery, and the code the original threshold proofs
used as their central example. Fault-tolerant syndrome extraction is
built so that any *single* fault anywhere in the correction gadget
(a bad gate, a bad measurement, a bad preparation) either gets corrected
or, at worst, produces a detectable, correctable error by
construction, as this course's decoding lessons required. A
genuine, *uncorrected* logical error therefore requires **at least two
independent physical faults** landing inside the same correction cycle:
one to introduce an error the code cannot distinguish from a different
one, or one to slip past the first layer of protection while a second
independently corrupts the recovery itself.

If each physical gate fails independently with probability $p$, the
probability that two specific faults both occur is $\sim p^2$; summing
over the (constant, gadget-dependent) number of ways two faults can
combine to cause a logical error gives a logical error rate at
**level 1** of concatenation:

$$
p_1 \approx c\,p^2
$$

for some constant $c$ set entirely by the specific fault-tolerant
gadget circuitry (how many locations a fault can occur at, how many
pairs of them combine into an uncorrectable error), not by anything
derived from first principles here.

### Concatenating: nesting the code inside itself

Concatenation replaces each of the level-1 code's 7 physical qubits with
another encoded block of the same code, one level deeper. A level-2
logical qubit is now built from $7^2 = 49$ physical qubits. Crucially,
the *inputs* to the level-2 correction gadget are no longer raw physical
qubits with error rate $p$. They are level-1 logical qubits, each
already suppressed to error rate $p_1 \approx cp^2$. The same two-fault
argument applies one level up, with $p_1$ standing in for $p$, and
iterating $L$ times gives the recursion that is the theorem's real
engine, unrolled below to the closed-form suppression (or blowup) it
produces:

<DerivationSteps>
  <DerivationStep annotation="The same two-fault argument that gave p_1 ≈ c p² applies one level up, with the level-1 logical qubit's own error rate p_1 now standing in for the physical rate p.">
    $$
    p_2 \approx c\,p_1^2 \approx c\,(cp^2)^2 = c^3 p^4
    $$
  </DerivationStep>
  <DerivationStep annotation="Generalizing the pattern across levels gives the recursion driving the whole theorem: each level's logical error rate depends on the previous level's the same way p_1 depended on p.">
    $$
    p_{k+1} \approx c\,p_k^2, \qquad p_0 \equiv p
    $$
  </DerivationStep>
  <DerivationStep annotation="Unrolling: p_1 = c p_0², so c p_1 = (c p_0)². Then c p_2 = (c p_1)² = (c p_0)⁴, and by induction c p_k = (c p_0)^(2^k).">
    $$
    c\,p_k = (c\,p_0)^{2^k}
    $$
  </DerivationStep>
  <DerivationStep annotation="Solving for p_L gives the double exponential the threshold theorem is named for.">
    $$
    p_L \;\approx\; \frac{1}{c}\left(c\,p_0\right)^{2^{L}}
    $$
  </DerivationStep>
</DerivationSteps>

Define
$p_{\text{th}} := 1/c$, the physical error rate at which $cp_0 = 1$, the
recursion's fixed point. Two regimes fall out immediately:

- **$p_0 < p_{\text{th}}$** (so $cp_0 < 1$): raising a number less than 1
  to a rapidly growing power $2^L$ drives it to zero, and it does so
  *doubly* exponentially fast in $L$: each additional level squares the
  previous suppression factor rather than merely multiplying it.
- **$p_0 > p_{\text{th}}$** (so $cp_0 > 1$): the same formula now blows
  up doubly exponentially. Concatenating *more* only makes the logical
  error rate worse, precisely mirroring the surface code's
  above-threshold behavior from the prerequisite lesson, via a
  completely different mechanism.

The word "threshold" is doing something specific here that "the error
rate has to be low enough" does not capture, and the sharpest way to see
it is to sweep $p_0$ across $p_{\text{th}}$ at fixed $L$ rather than
watching one fixed $p_0$ across levels:

That fixed crossing point is what makes $p_{\text{th}}$ a threshold and
not merely a rule of thumb. At $p_0=p_{\text{th}}$ exactly, the recursion
has $cp_0=1$, so $p_L=1/c=p_{\text{th}}$ for every $L$: encoding buys
nothing, no matter how much of it you do, and the curves all pin
themselves to that one point. On either side of it, adding a level
squares the accumulated factor rather than multiplying it: going from
$L=2$ to $L=3$ multiplies $p_L$ by $r^{2^2}$, which is a 16-fold
*improvement* at $r=0.5$ and a 5-fold *regression* at $r=1.5$. The same
hardware investment pays or charges depending only on which side of the
crossing the device sits, and the sign flips there. A hardware programme's
entire question is which side of that point it is on; how far from it is
a secondary question about how many levels to build.

### Inverting the recursion: how many levels does a target error rate need?

Solving $p_L = \varepsilon$ for $L$, with $r := cp_0 < 1$:

$$
\varepsilon = \frac{1}{c}r^{2^L} \;\;\Longrightarrow\;\; 2^L = \frac{\ln(1/(c\varepsilon))}{\ln(1/r)} \;\;\Longrightarrow\;\; L = \log_2\!\left(\frac{\ln(1/(c\varepsilon))}{\ln(1/r)}\right)
$$

The numerator grows only like $\ln(1/\varepsilon)$ for small
$\varepsilon$, and taking $\log_2$ of *that* is what makes
$L = O(\log\log(1/\varepsilon))$: reaching even an astronomically small
target logical error rate needs only a handful of concatenation levels.

### Why the overhead is polylogarithmic, not polynomial

Each concatenation level multiplies the physical qubit count by the
code's own qubit overhead $n$ (here $n=7$ for Steane), so $L$ levels use
$n^L$ physical qubits per logical qubit. Substituting $L$ from above and
using $n^{\log_2 X} = X^{\log_2 n}$:

<EquationReveal
  terms={[
    { id: "NL", symbol: "N_L", gloss: "Physical qubits needed per logical qubit after L levels of concatenation." },
    { id: "n", symbol: "n", gloss: "Physical qubits per encoded block for the code in use (n = 7 for the Steane code)." },
    { id: "L", symbol: "L", gloss: "Number of concatenation levels." },
    { id: "eps", symbol: "ε", gloss: "Target logical error rate the computation must reach." },
    { id: "r", symbol: "r", gloss: "r = c·p₀, the physical error rate scaled by the threshold constant, with r < 1 below threshold." },
    { id: "log2n", symbol: "log₂ n", gloss: "The fixed exponent set by the code's own qubit overhead: for Steane, log₂7." },
  ]}
>
  $$
  N_L = n^{L} = \left(\frac{\ln(1/(c\varepsilon))}{\ln(1/r)}\right)^{\log_2 n}
  $$
</EquationReveal>

The base of this power, $\ln(1/(c\varepsilon))$, grows only
*logarithmically* in $1/\varepsilon$, so $N_L$ grows like
$\big(\log(1/\varepsilon)\big)^{\log_2 n}$: a fixed power of a logarithm,
i.e. **polylogarithmic in $1/\varepsilon$**. This is the theorem's real,
precise quantitative content: not merely "arbitrarily reliable
computation is possible," but "arbitrarily reliable computation costs
only polylog overhead," a qualitatively different, far stronger claim
than a polynomial or exponential resource cost would be.

### What the theorem assumes, and where those assumptions bite

$p_{k+1}\approx c\,p_k^2$ is not an unconditional statement about noisy
quantum systems. It is the conclusion of a proof whose hypotheses are
worth naming, because a device can violate any of them while still
reporting a per-gate error rate below the quoted threshold:

- **Errors are local and independent, or nearly so.** The two-fault
  counting argument silently assumes faults at different locations are
  uncorrelated. A noise process that hits many qubits at once, or that
  correlates faults across a correction cycle, breaks the $p^2$ step
  directly rather than merely worsening the constant. Rigorous
  extensions to non-Markovian and weakly-correlated noise exist, and
  they buy back a threshold at the cost of a smaller constant and
  stronger locality assumptions on the system-bath coupling.
- **Fresh ancillas are available on demand.** Each correction round
  discards entropy into freshly prepared $|0\rangle$ states. A device
  that cannot supply them at the rate the syndrome extraction consumes
  them has no way to remove the entropy errors deposit, and no amount of
  concatenation substitutes for that.
- **Operations run in parallel, and classical control keeps up.**
  Concatenation only stays polylogarithmic in *time* if each level's
  correction gadgets run concurrently and the classical decoding keeps
  pace with syndrome extraction. Serialize them and the overhead
  argument above no longer describes the runtime.
- **The threshold constant $c$ is gadget-specific.** $c$ counts the pairs
  of fault locations in a particular fault-tolerant construction, so
  $p_{\text{th}}=1/c$ is a property of the construction, not of quantum
  mechanics. Two proofs of "the threshold theorem" can quote thresholds
  orders of magnitude apart and both be correct.

  title="A threshold proof with its noise model made explicit"
  source="Aliferis, Gottesman & Preskill, Quantum Information and Computation 6, 97 (2006) (arXiv:quant-ph/0504218)"
  url="https://arxiv.org/abs/quant-ph/0504218"
>
  A rigorous accuracy-threshold proof for concatenated distance-3 codes,
  written in a way that makes the assumptions above visible rather than
  buried: the noise is specified as a bounded-strength system-bath
  coupling rather than a stochastic per-gate failure probability, which

  threshold it proves is small and pessimistic by construction, which is

</ResearchConnection>

## Noise as a Fixed Point

<InsightBlock>
  Concatenation turns noise into a fixed point: below threshold, each
  extra level of encoding squares the previous suppression rather than
  just adding to it, so a handful of levels is enough to reach any target
  reliability at only polylogarithmic qubit cost.
</InsightBlock>

The Quantum Hardware track's noise-and-scaling course asked a question
it could not yet answer: as you scale up a device, do physical error
rates compound catastrophically, killing any hope of a long computation,
or can they be tamed? The threshold theorem is the mathematical fact
that answers it. Below $p_{\text{th}}$, errors do **not** compound
without bound. Concatenation (or, as the next section discusses, a
large-enough surface code) provably suppresses them arbitrarily far, at
a cost that grows only polylogarithmically in how reliable you need to
be. That is what makes "build colder, more precisely
controlled, lower-error qubits until you cross threshold, then let error
correction handle the rest" a coherent long-term engineering roadmap
rather than false hope. Every real hardware effort's obsession with
gate fidelity traces back to this theorem: crossing
$p_{\text{th}}$ is not one improvement among many; it is the qualitative
threshold between "no amount of encoding saves you" and "arbitrarily
long, arbitrarily reliable computation is achievable."

## Two Thresholds, Routinely Confused

<Callout type="warning">
**Treating different threshold theorems' numerical threshold values as
contradicting each other.** The original concatenated-code threshold
theorems are typically *fully rigorous, adversarial-noise-model proofs*,
but the constants they can actually prove tend to be small and
pessimistic (often quoted far below 1%, sometimes several orders of
magnitude smaller, depending heavily on the specific fault-tolerant
gadget and noise model assumed). Surface-code threshold estimates from
the prerequisite lesson, by contrast, are generally *numerical,
simulation-based* results for a specific noise model and a specific
decoder, and tend to land at far more hardware-friendly, roughly
percent-level physical error rates. Neither number is "the" threshold:
comparing threshold values across code families, proof techniques, and
noise-model assumptions is subtle, and a different quoted
number reflects different assumptions, not different underlying physics.
</Callout>

<Callout type="mistake">
**Reading "arbitrarily small logical error at polylog overhead" as
"logical error can be driven to exactly zero."** The theorem guarantees
$p_L \to 0$ as $L\to\infty$, and that polylog-in-$1/\varepsilon$ qubit
cost gets you to any *fixed*, arbitrarily small target $\varepsilon>0$:
it does not claim zero error is achievable, and it says nothing at all
about what happens if the physical error rate itself sits above
$p_{\text{th}}$, where (as the worked example above shows numerically)
the same machinery drives the logical error rate *up*, not down.
</Callout>

## Practice Questions

1. Using the same recursion $p_{k+1} \approx c\,p_k^2$ with $c = 10^4$,
   take a physical error rate three-quarters of the way to threshold,
   $p_0 = 0.75\,p_{\text{th}} = 7.5\times10^{-5}$. Compute $p_1$, $p_2$,
   and $p_3$, and compare how much more slowly this sequence collapses
   than the lesson's own $p_0 = 0.5\,p_{\text{th}}$ column in the
   worked-example table.

   <details className="answer-reveal">
   <summary>Answer</summary>

   $p_1=5.625\times10^{-5}$, $p_2=3.164\times10^{-5}$,
   $p_3=1.001\times10^{-5}$. Three levels of concatenation have bought a
   factor of $7.5$, where the same three levels at
   $p_0=0.5\,p_{\text{th}}$ bought a factor of $128$.

   Turning the crank:

   $$
   p_1 = 10^4(7.5\times10^{-5})^2 = 5.625\times10^{-5},
   $$

   $$
   p_2 = 10^4(5.625\times10^{-5})^2 = 3.164\times10^{-5},
   $$

   $$
   p_3 = 10^4(3.164\times10^{-5})^2 = 1.001\times10^{-5}.
   $$

   The closed form makes the comparison exact rather than impressionistic.
   With $r=cp_0$,

   $$
   \frac{p_L}{p_0} = r^{\,2^L-1},
   $$

   so three levels multiply the error rate by $r^7$. At $r=0.5$ that is
   $1/128$; at $r=0.75$ it is $0.1335$, a factor of $7.5$. A physical
   error rate only $1.5$ times worse produces a suppression $17$ times
   weaker, and both cost the identical $7^3=343$ physical qubits per
   logical qubit.

   The honest way to price that is to ask what $r=0.75$ must spend to
   match what $r=0.5$ achieves at three levels, namely
   $3.91\times10^{-7}$. Four levels gives $10^{-4}\times0.75^{16} =
   1.00\times10^{-6}$, still worse. Five levels gives
   $10^{-4}\times0.75^{32} = 1.00\times10^{-8}$, finally better. So
   $L=5$, at $7^5=16{,}807$ physical qubits per logical qubit against the
   other device's $343$. **A factor of $1.5$ in gate fidelity is worth a
   factor of $49$ in hardware**, and that ratio is the entire argument
   for why fabrication and control teams chase fidelity long after they
   are already below threshold.

   **The wrong turn** is reading "below threshold" as a binary that has
   been passed. Both devices are below threshold and both improve
   without limit, so the theorem's guarantee is satisfied in both cases.
   What differs is the base $r$ that gets raised to $2^L$, and since $L$
   enters only through an exponent while $r$ sets what is being
   exponentiated, no amount of concatenation compensates for a worse $r$
   in a fixed qubit budget. Being under the threshold is the entry
   requirement; the distance under it is the whole of the economics.

   </details>

2. Suppose a device instead operates at $p_0 = 1.2\,p_{\text{th}} =
   1.2\times10^{-4}$, above threshold but closer to it than the
   lesson's $p_0 = 1.5\,p_{\text{th}}$ case. Compute $p_1$ through $p_4$
   with the same recursion, and state whether four levels of
   concatenation help or hurt here, and by roughly what factor.

   <details className="answer-reveal">
   <summary>Answer</summary>

   They hurt, by a factor of about $15$.

   $$
   p_1 = 1.440\times10^{-4},\quad
   p_2 = 2.074\times10^{-4},\quad
   p_3 = 4.300\times10^{-4},\quad
   p_4 = 1.849\times10^{-3}.
   $$

   Each of those is $10^{-4}\times1.2^{2^k}$, and the same ratio formula
   as question 1 gives $p_4/p_0 = 1.2^{15} = 15.4$ directly. So $7^4 =
   2{,}401$ physical qubits have been spent per logical qubit to make
   that logical qubit fifteen times *less* reliable than one bare
   physical qubit. There is no reading of that trade under which it is
   worth making.

   The comparison with the lesson's $1.5\,p_{\text{th}}$ column is the
   interesting part. There the same four levels degrade the error rate by
   $1.5^{15}=438$, nearly thirty times worse than here. So being closer
   to threshold from above genuinely is less catastrophic, and that fact
   is a trap: a device at $1.2\,p_{\text{th}}$ can run a level-1 or
   level-2 experiment, see a logical error rate in the same order of
   magnitude as its physical one, and read that as "roughly break even,
   we are nearly there." The recursion is not nearly there. It is on the
   wrong side of a fixed point, and the only thing distinguishing $1.2$
   from $1.5$ is how fast the damage compounds.

   **The one diagnostic that works** is the sign of the change from level
   to level, not its magnitude. $p_1>p_0$ already, at the very first
   level, and that single comparison settles which side of threshold the
   device is on. It costs one level of encoding to measure and needs no
   knowledge of $c$ or $p_{\text{th}}$ at all. This is exactly the test
   the Willow result reports in the surface-code language: logical error
   rate falling as distance grows is the below-threshold signature, and
   the factor by which it falls is a secondary number.

   **A caveat the lesson flags and this case makes concrete.** Above
   threshold the recursion eventually returns values above $1$, which are
   not probabilities. Here that does not happen until $L=6$
   ($p_6\approx11.7$), so the four numbers above are at least
   self-consistent as probabilities. They are still not trustworthy in
   detail, because $p_{k+1}\approx cp_k^2$ counts only the leading
   two-fault term and that approximation degrades as $p_k$ grows. The
   qualitative conclusion, that concatenation makes things worse and
   worse the more of it you do, survives all of that; the specific $15.4$
   should be read as an order of magnitude.

   </details>

3. The lesson shows that reaching $\varepsilon = 10^{-18}$ from
   $p_0 = 0.5\,p_{\text{th}}$ needs $L = 6$ levels of the Steane code,
   costing $7^6 = 117{,}649$ physical qubits per logical qubit. Using
   $L = \log_2\!\big(\ln(1/(c\varepsilon))/\ln(1/r)\big)$ with the same
   $r = cp_0 = 0.5$, find the smallest integer $L$ needed to reach a
   far less demanding target of $\varepsilon = 10^{-9}$, and the
   corresponding physical-qubit cost per logical qubit.

   <details className="answer-reveal">
   <summary>Answer</summary>

   $L=5$, costing $7^5 = 16{,}807$ physical qubits per logical qubit.

   Substituting $c\varepsilon = 10^4\times10^{-9} = 10^{-5}$ and
   $\ln(1/r)=\ln2$:

   $$
   L = \log_2\!\left(\frac{\ln(10^{5})}{\ln 2}\right)
     = \log_2\!\left(\frac{11.513}{0.6931}\right)
     = \log_2(16.61) = 4.05 ,
   $$

   and since only whole levels exist, round **up** to $L=5$.

   Confirm against the recursion rather than trusting the rounding, because
   $4.05$ is uncomfortably close to $4$. Four levels give
   $p_4 = 10^{-4}\times0.5^{16} = 1.53\times10^{-9}$, which misses the
   $10^{-9}$ target, narrowly but genuinely. Five levels give
   $p_5 = 10^{-4}\times0.5^{32} = 2.33\times10^{-14}$, five orders of
   magnitude past it.

   **That overshoot is the real lesson here.** There is no configuration
   between $1.5\times10^{-9}$ and $2.3\times10^{-14}$. Concatenation
   squares the suppression at each step, so the available operating
   points are sparse, and a design that needs $10^{-9}$ ends up buying
   $10^{-14}$ and paying $7\times$ the qubits for the accuracy it did not
   ask for. The same granularity shows up in the surface code as the
   jump from distance $d$ to $d+2$, and in magic-state factories as the
   jump from one distillation round to two. Whole-number resources are
   why real resource estimates are so often dominated by rounding.

   **Now compare the two targets, which is where the polylogarithm stops
   being an asymptotic remark.** Relaxing the requirement from
   $10^{-18}$ to $10^{-9}$, a *billion-fold* weakening of the accuracy
   demand, saves exactly one level: $117{,}649$ qubits become $16{,}807$,
   a factor of $7$. That cuts both ways, and the direction that matters
   is the encouraging one. Since demanding a billion times more accuracy
   costs only $7\times$ the hardware, a fault-tolerant machine's size is
   set almost entirely by how many logical qubits and gates the algorithm
   needs, and almost not at all by how reliable each one has to be. That
   is the practical content of "polylogarithmic overhead," and it is why
   resource estimates spend their pages on gate counts rather than on
   target error rates.

   **The wrong turn** is taking $L=4.05$ and rounding to the nearest
   integer. The formula returns the real-valued level at which $p_L$
   would exactly equal $\varepsilon$; anything below it is a level that
   has not reached the target. Always round up, and when the fractional
   part is small, check the recursion directly, since $L=4$ misses here
   by only $53\%$ and a plot would not show the difference.

   </details>

## Summary

- The threshold theorem, proved independently by several groups
  (Shor, Aharonov–Ben-Or, Kitaev, Knill–Laflamme–Zurek, and others)
  around 1996–1998, showed that below a constant physical error rate
  $p_{\text{th}}$, concatenated encoding drives logical error
  *arbitrarily* low, resolving the era's genuine doubt about whether
  continuous, realistic noise could ever be tamed at all.
- The concatenated-code proof rests on one recursion,
  $p_{k+1}\approx c\,p_k^2$, unrolled to
  $p_L \approx (1/c)(cp_0)^{2^L}$: below threshold ($cp_0<1$) this is a
  double-exponential collapse; above it ($cp_0>1$), the identical formula
  is a double-exponential blowup.
- Inverting the recursion shows a target logical error rate
  $\varepsilon$ needs only $L=O(\log\log(1/\varepsilon))$ concatenation
  levels, and therefore only **polylogarithmic**, not polynomial or
  exponential, total qubit overhead in $1/\varepsilon$. That is the
  theorem's real quantitative content.
- The surface code's numerical, decoder-specific threshold estimates
  (prerequisite lesson) and the original concatenated-code proofs reach
  the same qualitative conclusion by different mechanisms, with
  different tradeoffs: rigorous-but-pessimistic versus
  numerical-but-realistic, not competing physics.
- This is the mathematical fact underwriting the Quantum Hardware
  track's entire scaling roadmap: below threshold, physical error
  rates do not compound without bound; they can be suppressed
  arbitrarily far at polylog cost.
