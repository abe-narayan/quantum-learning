export function invertTwoByTwo(M) {
  const a = M.get(0, 0);
  const b = M.get(0, 1);
  const c = M.get(1, 0);
  const d = M.get(1, 1);
  const det = a.mul(d).sub(b.mul(c));
  const detInv = new Complex(1, 0).div(det);
  return new Matrix([
    [d.mul(detInv), b.scale(-1).mul(detInv)],
    [c.scale(-1).mul(detInv), a.mul(detInv)],
  ]);
}

export function columnVector(values) {
  return new Matrix(values.map((v) => [new Complex(v, 0)]));
}

export function vectorNorm(M) {
  let sum = 0;
  for (let r = 0; r < M.rows; r++) sum += M.get(r, 0).magnitudeSquared();
  return Math.sqrt(sum);
}

export function expectationValue(stateVec, observable) {
  return stateVec.dagger().mul(observable).mul(stateVec).get(0, 0).re;
}

export function solveByCramer(M, rhs) {
  const det = M.get(0, 0).mul(M.get(1, 1)).sub(M.get(0, 1).mul(M.get(1, 0)));
  const detX = rhs.get(0, 0).mul(M.get(1, 1)).sub(M.get(0, 1).mul(rhs.get(1, 0)));
  const detY = M.get(0, 0).mul(rhs.get(1, 0)).sub(rhs.get(0, 0).mul(M.get(1, 0)));
  return new Matrix([[detX.div(det)], [detY.div(det)]]);
}

export function normalizedColumn(M) {
  return M.scale(1 / vectorNorm(M));
}

## HHL, Rebuilt on Newer Machinery

The underlying result, first published as Harrow, Hassidim, and Lloyd's
2009 algorithm (HHL) and now more cleanly derived as one instance of
QSVT, is real, and exactly as narrow as this lesson is about
to make precise.

HHL answers a
different question than "solve $Ax=b$" in the classical sense: given a
way to *quantumly* prepare $|b\rangle$ and a *quantum* black box for
$A$, produce a *quantum state* proportional to $A^{-1}|b\rangle$. Every
word in that sentence is load-bearing, and this lesson's job is to show
exactly which real problems that state is (and isn't) useful for, using
the QSVT machinery from the prerequisite lesson as the concrete
mechanism, not a black box of its own.

## Inverting A by Choosing the Right Polynomial

### The quantum linear systems problem, stated precisely

Let $A$ be Hermitian (WLOG: a non-Hermitian system $A'x=b$ embeds into
the Hermitian system $\begin{pmatrix}0&A'\\A'^\dagger&0\end{pmatrix}$
acting on an augmented space, so nothing is lost by assuming Hermitian
$A$ directly). Assume:

- a **block encoding** of $A$, normalized so $\|A\|\leq1$, with
  singular values $\sigma_i\in[1/\kappa,\,1]$, where
  $\kappa=\sigma_{\max}/\sigma_{\min}$ is $A$'s **condition number**;
- a way to **prepare** a quantum state $|b\rangle$ proportional to the
  target vector $b$.

The goal: produce (a state proportional to) $|x\rangle\propto
A^{-1}|b\rangle$, the solution of $Ax=b$, encoded as amplitudes over
$\log_2N$ qubits for an $N$-dimensional system.

### Realizing $A^{-1}$ via QSVT

The prerequisite lesson's entire point was that QSVT lets you apply
*any* polynomial $P$ (subject to a boundedness condition) to a
block-encoded matrix's singular values, essentially for free once the
signal-processing phases are found. The linear-systems problem is
exactly the special case below, for a normalizing constant $c$ chosen so
$|P(x)|\leq1$ on that range (QSVT's polynomials must stay bounded by 1
to remain implementable as part of a unitary circuit).

<EquationReveal
  terms={[
    { id: "P", symbol: "P(x)", gloss: "The QSVT polynomial being realized; here it is chosen to approximate matrix inversion." },
    { id: "c", symbol: "c", gloss: "A normalizing constant, chosen so |P(x)| stays ≤ 1 on the interval below, which P must satisfy to be implementable as part of a unitary circuit." },
    { id: "x", symbol: "x", gloss: "A stand-in for one of A's singular values." },
    { id: "kappa", symbol: "κ", gloss: "A's condition number, σ_max/σ_min. The interval [1/κ, 1] is exactly the range of singular values a block encoding of A can have." },
  ]}
>
$$
P(x)\approx \frac cx \quad\text{for } x\in[1/\kappa,\,1]
$$
</EquationReveal>

<TheoremBox title="Quantum linear systems via QSVT" provenance="cited">

Given a block encoding of Hermitian $A$ (singular values in
$[1/\kappa,1]$) and a state-preparation circuit for $|b\rangle$, applying
the QSVT circuit for $P(x)\approx c/x$ to $|b\rangle$ and post-selecting
the block encoding's ancilla on $|0\rangle$ produces a state proportional
to

$$
P(A)|b\rangle \approx c\,A^{-1}|b\rangle = |x\rangle,
$$

the solution of $Ax=b$, an immediate specialization of the prerequisite
lesson's QSVT theorem, with no new machinery beyond choosing this one
polynomial.

</TheoremBox>

**The regularization point.** $1/x$ is unbounded as
$x\to0$, so no bounded-degree polynomial can approximate it uniformly
all the way down to $x=0$. The obstruction is technical and well
known, and the literature does not gloss over it. What
makes the construction work at all is that the block encoding's
singular values are *bounded away from zero*, $x\geq1/\kappa$, by
assumption; the polynomial only has to approximate $c/x$ on
$[1/\kappa,1]$, and standard approximation-theory results (Chebyshev-type
constructions, cited here, not rederived) give a polynomial of degree
$O(\kappa\log(1/\epsilon))$ achieving accuracy $\epsilon$ on exactly that
truncated interval. A worse-conditioned $A$ (smaller $1/\kappa$, i.e.
larger $\kappa$) pushes the approximation domain closer to the
unbounded singularity, which is precisely why every version of this
algorithm's cost scales with $\kappa$, not just with $N$.

### Query complexity

The right way to characterize the cost is qualitative:
$\mathrm{poly}(\kappa,\,1/\epsilon,\,\log N)$ queries to the block
encoding and to the state-preparation circuit for $|b\rangle$. The
*exact* exponents on $\kappa$ and $1/\epsilon$ differ between HHL's
original 2009 bound and the best current QSVT-based constructions (and
have been improved more than once since), so citing one specific
exponent as if it were a fixed, permanent constant of the algorithm
misstates how this literature actually works. The durable
characterization, and the one this lesson commits to, is
$\mathrm{poly}(\kappa,1/\epsilon,\log N)$.

Compare this to the **classical** cost of solving a general
$N$-dimensional linear system: $O(N^3)$ for dense Gaussian elimination,
or, for the fairer comparison, $O(N\cdot\mathrm{poly}(\kappa))$ for a
sparse well-conditioned system via conjugate-gradient-type iterative
methods. Note that the classical iterative method's cost *also*
depends on $\kappa$, so a fair comparison must track $\kappa$ on both
sides, not quote a $\kappa$-free classical cost against a
$\kappa$-dependent quantum one.

## A State, Not a Vector of Numbers

<InsightBlock>
  The output is a quantum state, not a vector of numbers: the single
  most important, and most often glossed-over, fact about this entire
  algorithm family.
</InsightBlock>

For an $N$-dimensional problem, $|x\rangle$ lives on $\log_2N$ qubits,
and its $N$ amplitudes are *not* something you can read off by
measuring once. Fully reading out an $N$-dimensional amplitude vector to
precision $\epsilon$ requires, by standard state-tomography arguments,
resources that grow with $N$, and doing this would throw away exactly the
exponential-in-$N$ saving that made $\log_2N$ qubits attractive in the
first place. The algorithm is only useful when the actual object of
interest is a **small readout** extractable from $|x\rangle$ with a
handful of measurements: an expectation value $\langle
x|M|x\rangle$ for some observable $M$, a small number of specific
amplitudes, or a similar $O(1)$-sized quantity, and never the full solution
vector.

**A documented controversy.** Popular accounts of
HHL have repeatedly claimed "exponential quantum speedup for solving
$Ax=b$" without qualification; researchers in the field (including
Aram Harrow himself) have pushed back on exactly this over-claiming for
years. A full, honest accounting of when the speedup is real requires
**all four** of the following to hold simultaneously:

1. **$A$ is well-conditioned**: $\kappa$ doesn't grow with $N$ (or
   grows only polylogarithmically); the classical comparison must also
   use a $\kappa$-dependent method, not a $\kappa$-free one, to stay
   fair.
2. **$A$ has an efficient block encoding**: sparse, or otherwise
   structurally simple, so preparing the block-encoding circuit itself
   costs $\mathrm{polylog}(N)$, not $O(N)$.
3. **$|b\rangle$ is efficiently preparable**: a generic classical
   vector $b$ costs $O(N)$ just to load; only structured $b$ (e.g.
   itself the output of an efficient quantum circuit) avoids re-paying
   the $N$ you were trying to avoid.
4. **The desired output is a small readout**, not the full vector $x$.

A claim of "exponential speedup for linear systems" that is silent on
any of these four is incomplete at best. This is the pattern the
platform's later research-methods course teaches you to catch in real
papers, and the four conditions are not this lesson's invention.

A second caution belongs here too.

<ResearchConnection
  title="A quantum-inspired classical dequantization"
  source="Ewin Tang, 2018"
  url="https://arxiv.org/abs/1807.04271"
>
  Tang's "quantum-inspired" classical algorithm (originally for a
  recommendation-systems problem building on this same HHL-style
  construction) showed that, under a specific classical data-access
  model analogous to efficient quantum state preparation, a classical
  algorithm can sometimes match the quantum algorithm's polylogarithmic
  scaling for certain low-rank problems. That is a real **dequantization**
  result. It does not refute QSVT-based linear solvers in general, but it
  does show that condition (2)–(3) style assumptions can
  sometimes be satisfied classically too, for specific problem
  structures.
</ResearchConnection>

None of this makes the algorithm uninteresting. It makes precision
about the algorithm's conditional scope the whole point.

## A 2x2 System, Solved Both Ways

**A small, fully computed 2-dimensional (1-qubit) example.**
Take the real symmetric (hence Hermitian) matrix

$$
A=\begin{pmatrix}3&1\\1&3\end{pmatrix}
$$

computed here via this platform's actual `Matrix`/`Complex` classes
(`linA`), with a from-scratch `invertTwoByTwo` helper (the platform has
no general matrix-inverse routine, so this lesson implements the
standard 2×2 closed form directly, the same spirit as the prerequisite
courses' from-scratch `matrixExponential`).

**Eigenvalues and condition number, derived, not asserted.** From
$\mathrm{tr}(A)=6$ and $\det(A)=8$ (`linTrace`, `linDet`, both computed
directly from `linA`'s entries), the characteristic equation
$\lambda^2-6\lambda+8=0$ gives
$\lambda=\frac{6\pm\sqrt{36-32}}2=\frac{6\pm2}2$, so

$$
\lambda_{\max}=4,\qquad\lambda_{\min}=2,\qquad\kappa=\frac{\lambda_{\max}}{\lambda_{\min}}=2
$$

(`linEigenMax`, `linEigenMin`, `linKappa`), a well-conditioned
matrix. Rescaling by $\|A\|=\lambda_{\max}=4$ to fit the block-encoding
convention $\|A\|\leq1$ (`linATilde = linA/4`) gives singular values
$\sigma_{\max}=1$, $\sigma_{\min}=0.5=1/\kappa$ (`linATildeSigmaMax`,
`linATildeSigmaMin`), exactly the $[1/\kappa,1]$ range the polynomial
$P(x)\approx c/x$ above needs to approximate on, with the *same* $\kappa=2$,
since condition number is scale-invariant.

**Classical solution, computed and verified.** For $b=(1,1)^\top$
(`linB1`), direct inversion gives

$$
x=A^{-1}b=\frac18\begin{pmatrix}3&-1\\-1&3\end{pmatrix}\begin{pmatrix}1\\1\end{pmatrix}=\begin{pmatrix}0.25\\0.25\end{pmatrix}
$$

(`linX1`), and multiplying back out, `linCheck1` $=A\,x=(1,1)^\top=b$
exactly, confirming the solution by direct computation.
Its norm is $\|x\|=\sqrt{0.25^2+0.25^2}=\frac1{2\sqrt2}\approx0.353553$
(`linX1Norm`), so the normalized direction (`linX1Normalized`) is

$$
\frac x{\|x\|}=\left(\frac1{\sqrt2},\,\frac1{\sqrt2}\right)\approx(0.707107,\,0.707107)
$$

This is exactly the single-qubit $|+\rangle$ state.

**What the quantum algorithm's output represents.** The state
$|x\rangle$ that a real run of this algorithm would (ideally, in the
zero-error limit) produce has *these exact same two numbers* as its
amplitudes: $|x\rangle=0.707107\,|0\rangle+0.707107\,|1\rangle$. This
is the entire point made concrete: the state numerically
encodes the classical answer's direction exactly, it just isn't something you
can read out as "$0.25,0.25$" by measuring once. What you *can* extract
with a handful of measurements is a small readout, e.g. the
single-qubit observable expectation values (computed directly via
`expectationValue`, i.e. $\langle x|M|x\rangle$ using this platform's
actual `PAULI_Z`/`PAULI_X` matrices and `Matrix.dagger`):

$$
\langle x|Z|x\rangle = |0.707107|^2-|0.707107|^2 = 0 \qquad(\texttt{linExpectationZ1})
$$

$$
\langle x|X|x\rangle = 2(0.707107)(0.707107) = 1 \qquad(\texttt{linExpectationX1})
$$

Both are exactly computed numbers extractable from $O(1)$ repeated
measurements, and each is useful global information in its own right, while the full pair
$(0.707107,0.707107)$ that produced them is not something you get back
directly at all.

**A second $b$, to confirm this isn't a coincidence of one example.**
For $b=(1,-1)^\top$ (`linB2`), the same machinery gives $x=(0.5,-0.5)$
(`linX2`, verified again via `linCheck2`$=A\,x=(1,-1)^\top=b$), normalized
to $(1/\sqrt2,\,-1/\sqrt2)\approx(0.707107,-0.707107)$ (the $|-\rangle$
state), with $\langle Z\rangle=0$ again but now $\langle
X\rangle=-1$ (`linExpectationZ2`, `linExpectationX2`): a different
solution vector, correctly reflected in a different readout, computed
by the same route both times.

## The Readout Trap

<Callout type="mistake">
**Thinking "the algorithm outputs $x$" means you can print out
$(0.707107,\,0.707107)$.** It means a quantum state has those two
numbers as amplitudes. Turning that state back into two classical
floating-point numbers by measurement would require enough repeated
shots to resolve each amplitude to your target precision. For a
2-dimensional toy example that is cheap and unremarkable, but the whole
reason this algorithm is interesting is its behavior as $N$ grows, and
full amplitude readout's cost grows with $N$ too, erasing the
$\log_2N$-qubit advantage that motivated using it. If your application
needs the full vector $x$ back in classical memory, this
algorithm is not the tool for that job, regardless of $\kappa$.
</Callout>

<Callout type="warning">
**Quoting "$\mathrm{poly}(\log N)$" as if $\kappa$ were always small.**
The query count is $\mathrm{poly}(\kappa,1/\epsilon,\log N)$, and
$\kappa$ is doing real work in that expression. For many
practically-relevant matrices (e.g. discretized differential operators),
$\kappa$ grows polynomially with the problem's own resolution, which can
quietly erase the advantage the $\log N$ term seemed to promise. Always
ask what $\kappa$ does as the problem scales, not just what $N$ does.
</Callout>

## Practice Questions

1. This lesson's worked example has $\kappa=2$ and a classical solution
   readable in one step (it's 2-dimensional). Explain concretely, in
   your own words, why the *same* algorithm's value only shows up at
   large $N$, and only for a small readout, not in a toy example like
   this one. Then make the $\kappa$ half of that story quantitative: using
   the degree estimate $\deg\approx\kappa\ln(1/\epsilon)$, compare the
   polynomial degree this $\kappa=2$ example needs at $\epsilon=10^{-3}$
   with the degree needed for a discretized one-dimensional Laplacian on
   $N=2^{20}$ grid points, whose condition number grows like $N^2$, at the
   same $\epsilon$. Say what that does to the $\mathrm{polylog}(N)$
   headline.

   <details className="answer-reveal">
   <summary>Answer</summary>

   **Why a toy case cannot show the value.** The algorithm's entire selling point is that a state on $\log_2N$ qubits carries $N$ amplitudes, so the *representation* of the answer is exponentially compressed. At $N=2$ that compression buys one qubit against two numbers, which is nothing. Worse, the two things the algorithm charges you for are both trivially cheap here: the classical alternative is a $2\times2$ inverse computable by hand, and reading the full state out costs a handful of shots. There is no regime in a two-dimensional example where anything can be exponentially better than anything else, because there is no exponent.

   The small-readout half is the same argument run at the output. Even at large $N$, the state $|x\rangle$ is only useful if what you want is extractable in $O(1)$ measurements: an expectation $\langle x|M|x\rangle$, an overlap, a handful of named amplitudes. If you want the whole solution vector back in classical memory, you must resolve $N$ amplitudes to precision $\epsilon$, and the shot count for that grows with $N$, which cancels the $\log_2 N$ advantage exactly. So the algorithm is not "a faster linear solver"; it is a faster way to compute a *scalar functional* of a solution you never see.

   **Now the $\kappa$ arithmetic, which is where most of the honest bad news lives.**

   For this lesson's example, $\kappa=2$ and $\epsilon=10^{-3}$:

   $$
   \deg\approx\kappa\ln(1/\epsilon)=2\times6.9078=13.82 \longrightarrow 14 .
   $$

   Fourteen. Cheap, and it is cheap because $\kappa$ is $2$.

   For the discretized one-dimensional Laplacian on $N$ interior grid points, the eigenvalues are $4\sin^2\!\big(k\pi/(2(N+1))\big)$, giving $\kappa=\sin^2\!\big(N\pi/(2(N+1))\big)/\sin^2\!\big(\pi/(2(N+1))\big)$, which is $(2N/\pi)^2$ to excellent accuracy. At $N=2^{20}=1{,}048{,}576$ this evaluates to

   $$
   \kappa=4.456\times10^{11},
   $$

   and the same degree estimate at $\epsilon=10^{-3}$ gives

   $$
   \deg\approx4.456\times10^{11}\times6.9078=3.08\times10^{12} .
   $$

   Three trillion queries to the block encoding, for a problem whose $\log_2N$ is $20$.

   **What that does to the headline.** It destroys it. The query count is $\mathrm{poly}(\kappa,1/\epsilon,\log N)$, and here $\kappa$ scales as $N^2$, so the cost scales as $N^2\log(1/\epsilon)$: *polynomial* in $N$, not polylogarithmic. The $\log N$ factor is still there and is still doing what it advertises; it is simply irrelevant next to a factor growing as $N^2$. Meanwhile the same tridiagonal system is solvable classically in $O(N)$ time by the Thomas algorithm, so on this problem the quantum method is asymptotically *worse* than the obvious classical one, by roughly a factor of $N$.

   Two wrong turns are worth separating here.

   The first is treating $\kappa$ as a constant of the matrix rather than a function of the problem size. In this example $\kappa$ is what carries the size dependence, and the $N$ that appears in $\log N$ and the $N$ hidden inside $\kappa$ are the *same* $N$. Reading the complexity as "polylog in the dimension, times some condition-number factor" invites you to think of the two as independent knobs. They very often are not, and discretized differential operators, the most commonly cited application, are exactly the case where they are not.

   The second is concluding that the algorithm is therefore useless. It is not; it is *conditional*, and condition (1) of the four-condition list is precisely the condition this example fails. Preconditioning, or a problem whose $\kappa$ genuinely stays bounded as $N$ grows, puts you back on the good side of it. The point of running the number is to see that "well-conditioned" is a hypothesis with teeth, not a footnote: between $\kappa=2$ and $\kappa=4.5\times10^{11}$ lies the difference between $14$ queries and $3\times10^{12}$.

   </details>

2. Suppose a paper claims "exponential quantum speedup" for solving a
   linear system, and confirms condition (1) ($A$ well-conditioned) and
   condition (2) (an efficient block encoding for $A$) from this
   lesson's four-condition list, but says nothing about how $b$ is
   prepared or what the desired output is. Is the claim complete? Name
   the specific missing condition(s) and what could go wrong if they
   fail.

   <details className="answer-reveal">
   <summary>Answer</summary>

   The claim is **not complete**. Conditions (3) and (4) are both missing, and either one failing alone is enough to erase the entire exponential advantage.

   **Missing condition (3): $|b\rangle$ efficiently preparable.** The algorithm assumes a circuit that produces the state $|b\rangle\propto b$. If $b$ is an arbitrary classical vector of $N$ numbers sitting in a file, loading it into amplitudes costs $\Omega(N)$ in general, because $N$ numbers have to be read at least once. Paying $O(N)$ at the door and then celebrating a $\mathrm{polylog}(N)$ solve is bookkeeping, not a speedup: the total is still $\Omega(N)$. The advantage survives only when $b$ is *structured*, for instance uniform, sparse, described by a short formula, or itself the output of an earlier efficient quantum circuit. A QRAM assumption can also supply it, but that is an assumption about hardware that does not yet exist at scale, and it must be stated rather than absorbed.

   **Missing condition (4): the output is a small readout.** If the paper wants the full solution vector $x$ back in classical form, it has to resolve $N$ amplitudes to precision $\epsilon$, and the measurement cost grows with $N$. Same arithmetic as condition (3), now at the exit instead of the entrance. The speedup survives only for an $O(1)$-sized functional of $x$: an expectation $\langle x|M|x\rangle$, an overlap with a reference state, a few named amplitudes.

   **Why silence on these two is the common failure rather than a rare one.** Conditions (1) and (2) are properties of the *matrix*, which papers naturally discuss because they are what the algorithm's theorem statement quantifies over. Conditions (3) and (4) are properties of the *interface*, the input at one end and the desired answer at the other, and they are exactly the two that a complexity statement about the solve step can be true while being silent about. Aaronson's "Read the fine print" is largely an enumeration of this asymmetry.

   There is a third thing worth checking that is not on the list at all, and a careful reader should ask for it: whether the same access assumptions could be granted classically. Tang's dequantization results show that for certain low-rank structures, a classical algorithm handed an analogous sampling-access model matches the polylogarithmic scaling. So even a paper that satisfies all four conditions has not automatically demonstrated a quantum advantage; it has demonstrated a quantum algorithm whose classical counterpart under matched assumptions still has to be ruled out.

   The wrong turn worth naming is treating the four conditions as a checklist where partial credit accumulates. It does not. They are conjunctive, and the total cost is the product of the stages, so a single $\Omega(N)$ stage anywhere sets the whole result to $\Omega(N)$ no matter how good the other three are. Two out of four confirmed is not half a speedup; it is no established speedup at all.

   </details>

3. Using this lesson's exact worked numbers, verify by direct
   computation that $\langle x|Z|x\rangle=0$ for the normalized state
   $(1/\sqrt2,\,1/\sqrt2)$, and explain why this is a legitimate,
   informative computed result rather than a sign that something failed.

   <details className="answer-reveal">
   <summary>Answer</summary>

   **The computation.** $Z=\mathrm{diag}(1,-1)$, so for $|x\rangle=\tfrac1{\sqrt2}|0\rangle+\tfrac1{\sqrt2}|1\rangle$,

   $$
   \langle x|Z|x\rangle=\left|\tfrac1{\sqrt2}\right|^2-\left|\tfrac1{\sqrt2}\right|^2=0.5-0.5=0 .
   $$

   Running it through the platform's own `expectationValue(linX1Normalized, PAULI_Z)` with the real `PAULI_Z` matrix and `Matrix.dagger` returns exactly $0.000000$.

   **Why this is a result and not a failure.** $\langle Z\rangle$ is the difference between the probability of measuring $0$ and the probability of measuring $1$. Zero means those two probabilities are equal, which is a genuine, checkable statement about the solution: its weight is split evenly between the two basis directions. Nothing has cancelled, nothing has decohered, and nothing was lost. Compare $\langle X\rangle=1$ on the same state, which is the largest value $X$ can take, since $X$'s eigenvalues are $\pm1$: the state is exactly $X$'s $+1$ eigenvector. One observable reads its extreme value and the other reads its midpoint, and both are facts about the same state.

   The instinct that a zero must mean an error comes from treating an expectation value like a signal amplitude, where zero means nothing arrived. An expectation value is a *balance*, and balanced is one of the values it is supposed to be able to report.

   **What $\langle Z\rangle=0$ genuinely does not tell you, which is the more useful half of the answer.** It does not identify the state. The other worked case, $b=(1,-1)^\top$, gives $|x\rangle=\tfrac1{\sqrt2}|0\rangle-\tfrac1{\sqrt2}|1\rangle$, and that state also has $\langle Z\rangle=0$. So does $\tfrac1{\sqrt2}(|0\rangle+i|1\rangle)$, and so does the maximally mixed state. What separates them is $\langle X\rangle$: $+1$, $-1$, $0$ and $0$ respectively. Pinning down even a single qubit takes three numbers, $\langle X\rangle,\langle Y\rangle,\langle Z\rangle$, and that is the readout limitation of the whole algorithm in its smallest possible instance. One expectation value is one number, an $N$-dimensional state has far more than one number in it, and the gap between those two facts is exactly what condition (4) is about.

   **One caution about this particular worked example.** In both of the lesson's cases the solution direction turns out to equal the input direction: $b=(1,1)^\top$ gives $|x\rangle=|+\rangle$ and $b=(1,-1)^\top$ gives $|x\rangle=|-\rangle$. That is not the algorithm being trivial, it is those two $b$'s being *eigenvectors* of $A$. Writing $A=3I+X$ makes it immediate: $A|\pm\rangle=(3\pm1)|\pm\rangle$, so $A^{-1}$ acts on them by a scalar and cannot move their direction at all. Any conclusion of the form "the output state just reproduces the input" is reading an artifact of the chosen $b$.

   Take $b=(1,0)^\top$ instead, which is not an eigenvector. Then

   $$
   x=A^{-1}b=(0.375,\,-0.125),\qquad \frac{x}{\|x\|}=(0.948683,\,-0.316228),
   $$

   with $\langle Z\rangle=0.8$ and $\langle X\rangle=-0.6$, against the input state's $\langle Z\rangle=1$ and $\langle X\rangle=0$. The inversion has genuinely rotated the state, and the readouts move accordingly. That is the case worth carrying forward as the mental picture.

   </details>

## Summary

- The quantum linear systems problem takes a block encoding of
  Hermitian $A$ (singular values in $[1/\kappa,1]$) and a preparable
  $|b\rangle$, and produces $|x\rangle\propto A^{-1}|b\rangle$ via QSVT
  applying a polynomial approximation to $1/x$, regularized because $1/x$
  is unbounded near $0$. This works only because the block
  encoding keeps singular values bounded away from zero.
- Cost is $\mathrm{poly}(\kappa,1/\epsilon,\log N)$ queries;
  the classical comparison is $O(N^3)$ (dense) or
  $O(N\cdot\mathrm{poly}(\kappa))$ (sparse, conjugate-gradient-type,
  $\kappa$-dependent just like the quantum cost), an exponential
  advantage in $N$ that is conditional on $A$ being well-conditioned, an
  efficient block encoding existing, $|b\rangle$ being efficiently
  preparable, and the desired output being a small readout, not the full
  vector.
- The single most important, most often glossed-over fact: the output
  is a quantum state whose amplitudes numerically equal the solution's
  direction (verified explicitly here for a real 2×2 system, both
  $b=(1,1)^\top$ and $b=(1,-1)^\top$, against direct classical
  inversion), but that state is not classically readable as a vector
  without paying a cost that erases the speedup. Only a small readout
  like $\langle x|M|x\rangle$ preserves the advantage.
